# Корпус чужих случаев

**Что это.** Размеченные случаи из **настоящих чужих репозиториев** с ожидаемым вердиктом нашего
гейта. Прогон — `node evals/run.mjs`, он же объявлен гейтом `evals` и идёт в каждом `doctor --run`.

## Зачем отдельно от образцов red/green

У каждой записи каталога есть свои образцы. Их писал **тот же человек, который писал гейт**, —
они зелёные по построению и проверяют, что гейт согласен сам с собой.

Замер по 70 чужим репозиториям 14–15 сентября 2026 нашёл **пять ложных срабатываний**, которых
наши образцы не видели ни разу:

> **2026-09-15: две записи, породившие большую часть этой таблицы, УДАЛЕНЫ из каталога.**
> `entry-links-exist` дал восемь ложных, `no-phantom-package` — четыре, и ни одного
> подтверждённого настоящего на 400 репозиториев. Обе читали свободный текст, а не опознавали
> конструкцию. Решение владельца: хрупкие записи не чинят, их убирают. Случаи по ним из корпуса
> тоже убраны — сторожить нечего.

| что мы обвиняли | чем это оказалось | проверено |
|---|---|---|
| `../../releases` | так сам GitHub предлагает ссылаться на выпуски | страница отдаёт 200 |
| `assets/x.gif?raw=1` | строка запроса — не часть имени файла | файл на диске есть |
| `/issues` | путь от корня сайта, а не файл | — |
| `articles/x.html` | страницу собирает генератор при публикации | 200 на их сайте |
| `node "$CLAUDE_PROJECT_DIR/.claude/hooks/x.mjs"` | путь внутри кавычек вместе с переменной | файл на месте, 200 |

Каждое из них — письмо, которое ушло бы человеку с подписью «я проверил это руками». Поэтому
ложные лежат здесь наравне с настоящими: **случай с ожиданием «зелёное» так же обязателен, как с
ожиданием «красное»**.

## Одна ошибка, двенадцать лиц

Полный список — машиной, чтобы он не разошёлся с корпусом: `node evals/run.mjs --list`.

Разбор 2026-09-15 показал, что двенадцать наших ложных срабатываний — это **не двенадцать
ошибок, а одна**:

> Мы судили строку как путь на диске или имя пакета, **не зная, чем она разрешается**.

Разрешало её то, чего у нас нет: адрес на github.com (`../../releases`, `/issues`), генератор
сайта (`articles/x.html`), соседний репозиторий вики, переменная окружения
(`${CLAUDE_PLUGIN_ROOT:-.}`), рабочая область самого проекта (`@automattic/search`), английская
фраза вокруг (`yarn add a visual dimension…`).

**Почему чинить по одному — это костыли.** Список исключений внутри каждого гейта через три
правки разойдётся со списком в соседнем, и дважды пойманная беда вернётся через тот гейт, куда
её не дописали. Поэтому решение вынесено в общий шов `kit/gates/_target.sh` — один ответ на
вопрос «можем ли мы вообще разрешить эту строку».

**И неразрешённое больше не прячется.** Раньше такие цели молча пропускались — то есть «не
смогли проверить» выдавалось за «чисто», ровно то, за что мы ругаем чужие инструменты. Теперь
гейт печатает их числом и причинами:

```
  не проверено: 4 — цели, которые мы не можем разрешить:
     2 адрес на github.com
     2 страницу собирает генератор сайта
```

## Правило входа

Случай входит в корпус **только с источником**: настоящий чужой репозиторий и то, чем проверено —
код HTTP, ответ реестра npm, ссылка на коммит. Случай, придуманный за столом, меряет наш вкус, а
корпус заводился ровно чтобы перестать мерить себя.

## Что считается, а что нет

- **Совпало / не совпало** по каждому случаю — сторож от возврата беды.
- **Точность по гейту** — доля случаев, где мы обещаем красное и получаем красное.
- **Полноты здесь нет и быть не может.** Сколько бед мы вообще не видим, корпус не знает: в нём
  лежит только то, что мы уже заметили. Делать вид, что это «качество в процентах», — то же
  враньё, что зелёная галочка на выключенной проверке.
- **«Инструмента нет» — не «прошло».** Случай, чей гейт делегирован внешней программе, при её
  отсутствии печатается отдельной строкой «НЕ ПРОВЕРЕНО» и в зачёт не идёт.

## Петля, которая сама себя пополняет

```
замер по чужим репозиториям   (research/outreach/scan.sh)
        ↓ срабатывание
проверка у первоисточника     (код HTTP, реестр, их же коммиты)
        ↓
   настоящее? ──да──→ письмо человеку   (research/outreach/LETTER.md)
        │                    ↓
        └──нет──→ починка гейта         и в обоих случаях — случай сюда
```

Каждый проход замера либо даёт письмо, либо ловит наше враньё. И то и другое кончается новым
случаем в корпусе, который больше не даст беде вернуться.

## Как добавить случай

Файл `evals/cases/<имя>.json`:

```json
{
  "gate": "entry-links-exist",
  "expect": "green",
  "source": { "repo": "владелец/репозиторий", "checked": "чем проверено и когда" },
  "why": "почему вердикт именно такой",
  "requires": "slopcheck",
  "files": { "AGENTS.md": "# свод\n\n[ссылка](../../releases)\n" }
}
```

`expect` — `red`, `green` или `cannot`. `requires` — имя внешней программы, без которой случай
не проверяется (необязательно). Файлы — **минимальное воспроизведение**, а не копия чужого кода:
копия переносится по лицензии и проверяет то же самое, только медленнее.
