## 1. Харнес-инжиниринг: OpenAI (фев) + Anthropic Managed Agents (апр, новее)

**OpenAI «Harness Engineering»** (Ryan Lopopolo, 11.02.2026; ✓ текст у нас, ◐ часть цифр через InfoQ) —
внутренний продукт **~1М строк, 0 строк руками**, пишет Codex; люди управляют, агенты действуют. Главное:
- **Среда важнее кода:** «какой возможности не хватает и как сделать её **понятной (legible) и обязательной
  (mandatory)** для агента?» DFS-декомпозиция; цикл Ральфа Виггама (крутить до зелёного).
- **Agent-legibility:** приложение поднимается **per git-worktree**; Chrome DevTools в рантайме агента (DOM/
  скриншоты) → воспроизводит баг, проверяет фикс; **наблюдаемость per-worktree** (Vector→Victoria, LogQL/
  PromQL/TraceQL) → промпты «старт < 800 мс». Запуски **>6 ч**.
- **Знания репо = система учёта:** НЕ один толстый AGENTS.md (4 провала: контекст дефицитен / «важно всё» =
  неважно ничего / гниёт / непроверяемо), а **оглавление (~100 строк) + дерево `docs/`** (design-docs,
  exec-plans, generated/db-schema, references/*-llms.txt, QUALITY_SCORE/RELIABILITY/SECURITY); прогрессивное
  раскрытие; линтеры/CI на свежесть; **doc-gardening агент** открывает PR на устаревшее.
- **«Чего нет в контексте — нет»** → весь контекст кодировать в репо как версионируемые артефакты.
- **Слоистая архитектура «под агента»:** `Types→Config→Repo→Service→Runtime→UI` + сквозное через `Providers`;
  инварианты держат **кастомные линтеры + структурные тесты** (ошибка линтера **встраивает инструкцию по
  починке**); «обеспечиваем инварианты, не детали»; «архитектура на 100 инженеров — раннее предусловие».
- **Мерж:** минимум блокирующих гейтов, PR недолговечны, flaky — перезапуском; «фиксы дёшевы, ожидание дорого».
- **Энтропия/GC:** ручная уборка по пятницам **не прижилась** → «золотые принципы» в репо + фоновые Codex-
  задачи на дрейф (refactor-PR < 1 мин, авто-мерж); техдолг = кредит с высокой ставкой, гасить понемногу.
- Вывод: **дисциплина — в структуре, а не в коде.**

**Anthropic «Managed Agents: Decoupling brain from hands»** (08.04.2026; ✓) — ⚠️ **новее, развивает OpenAI:**
- Разделить **«мозг» (Claude+харнес)** и **«руки» (песочницы)** за стабильными интерфейсами (`execute()`,
  `getEvents()`); инфра как **«cattle, not pets»** — падает/заменяется независимо.
- **Харнес кодирует быстро-протухающие допущения о слабостях модели** (логика reset под «context anxiety»
  Sonnet 4.5 стала мёртвым грузом на Opus 4.5) → **виртуализировать**, держать **model-version-agnostic**.
- **Durable session log ВНЕ контекстного окна** (расследовать прошлое без необратимой обрезки); credentials
  изолированы от генеримого кода; stateless-харнес срезал **p50 TTFT ~60%**.

→ **для memo:** дерево `docs/` (есть) + QUALITY_SCORE/doc-gardening; agent-legibility = наш трейс + RO-
телеметрия; жёсткие границы слоёв + линтеры с подсказкой-в-ошибке (когда пойдёт код); brain/hands + session-
log-вне-контекста; харнес model-agnostic.

## 2. Anthropic: дизайн агентов и Claude Code (✓ eng-статьи + доки)

**Workflow vs agent:** workflow — заранее заданные пути; agent — «LLM в цикле использует тулы на обратной
связи из среды». **Начинай просто** (augmented LLM); сложность — только когда измеримо лучше; фреймворки
скрывают промпты — начинай с сырых API. **Три принципа:** простота · прозрачность · тщательный **ACI**
(agent-computer interface).

**Subagents vs agent teams:** subagent — свой контекст/тулы, **только отчитывается** (дёшево; лучшее —
ресёрч + **верификация со свежим контекстом**, без confirmation bias); teams (экспериментально) — общаются
mailbox'ом, общий task-list; дорого (линейно). Старт **3–5**, **5–6 задач** на участника; «три
сфокусированных > пяти разбросанных»; сильно — **дебаг конкурирующих гипотез** (адверсариально опровергают).

**Контекст-инжиниринг:** цель — **«наименьшее множество высокосигнальных токенов»**; context rot (растёт
число токенов → падает recall); just-in-time retrieval (лёгкие идентификаторы, грузить тулами); три стратегии
для долгого: **compaction** (саммари у лимита, сохранять решения/баги), **structured note-taking**, **саб**
(исследует десятки тыс → отдаёт 1–2 тыс саммари).

**CLAUDE.md:** читается в начале сессии как **user-сообщение** (влияет, но **не енфорсится** — жёсткое через
**hook**); порядок широкое→специфичное, конкатенация; вложенные грузятся **по требованию**; корневой
**переживает `/compact`**, вложенные нет; цель **<200 строк** («раздутый → Claude игнорирует инструкции»).
`.claude/rules/` с `paths:`-глобами грузятся только при касании файла. Auto-memory: `MEMORY.md` индекс,
первые 200 строк/25KB.

**5 принципов тул-API** (для нашего Runtime API!): (1) **консолидировать** домен-операции, не оборачивать
эндпоинты (`get_customer_context`, не три геттера); (2) **namespacing** (`asana_search`); (3) **высокосигнальный
вывод** — естественные имена, не uuid; опц. `response_format` (~⅓ экономии); (4) **токен-эффективность** —
пагинация/кап (Claude Code 25000 токенов), при усечении говорить как уточнить; (5) **промпт-инжиниринг
описаний тулов** + **направляющие ошибки** («ожидалось high|medium|low; ты дал 'critical'»). **Тест выбора
тула:** «если человек не скажет, какой тул применить — агент тем более». **Poka-yoke** (абсолютные пути).

**Workflow Claude Code:** Explore→Plan→Code→Commit; **дать способ верификации** (тесты/сборка/линтер/скриншот-
дифф) + гейты (промпт→`/goal`→**Stop hook**→свежий саб-ревьюер); **показывать доказательство**;
`AskUserQuestion`→`SPEC.md`→свежая сессия. **5 паттернов провалов:** kitchen-sink (`/clear`) · бесконечные
коррекции (после 2 — `/clear`+лучший промпт) · переспецифицированный CLAUDE.md · trust-then-verify gap («не
можешь проверить — не выкатывай») · бесконечный explore.

→ **для memo:** Runtime API строить по 5 принципам (но для бенчмарка **дозировать «помощь» ошибок** — влияет
на сложность); анти-чит — хуками/правами, **не текстом промпта** (CLAUDE.md лишь советует); компакшен/auto-
memory — вектор **утечки между задачами** → для чистых прогонов отключать.

## 3. KV-кэш и экономика контекста (Manus + provider-docs; ✓)

**«KV-cache hit rate — самая важная метрика продакшн-агента».** Агент в цикле: input:output ≈ **100:1** →
почти весь расход на input, кэш бьёт ~99% счёта. Кэшированный токен ~**10×** дешевле (Sonnet: $0.30 vs
$3/MTok) + пропускает prefill (падает TTFT).

**Анти-паттерны (и фиксы):**
- **Нестабильный префикс (#1):** «1 токен инвалидирует кэш с этого места»; **таймстемп-в-секундах в начале
  системного промпта** → 0% hit. Фикс: префикс байт-стабилен, время — в конец/огрубить.
- **Не-append-only / нестабильный порядок JSON-ключей** → `json.dumps(sort_keys=True)`, особенно для **схем
  тулов**.
- **Динамика рано** → `tools → system → long-lived → variable` (динамика в конец).
- **Round-robin роутинг** убивает кэш (кэш локален машине) → **sticky по session-id** / `prompt_cache_key`.
- Anthropic: 4 брейкпоинта, читать 0.1×/писать 1.25×–2×, минимум ~1024 токена (иначе тихо не кэшируется),
  прогрев `max_tokens:0`.

**6 уроков Manus:** проектируй вокруг кэша · **маскируй тулы логитами, не удаляй** (удаление спереди
инвалидирует кэш) · **файловая система как контекст** (обратимое сжатие: оставлять URL/путь) · **рецитация**
(`todo.md` толкает цель в недавнее внимание; ~50 вызовов/задача) · **держи ошибки в контексте** («без
доказательства модель не адаптируется») · **не зафьюшоть себя** (вносить разнообразие).

→ **для memo:** KV-cache hit rate — кандидат в **метрику качества оцениваемого агента**; наш тул/рантайм-API —
**байт-стабильный + детерминированно сериализованный** (sorted keys), динамику платформы (task_id, seed) — в
конец, sticky-роутинг, прогрев общего префикса.
