# Дип-ресёрч 2026-07-05: слепые зоны харнеса и платформы (4 агента)

> **Что это.** Сводка целевого gap-ресёрча: 4 параллельных агента искали **дельту** к уже внедрённому
> набору (см. `agent-harness-playbook.md` + ADR 006) по углам: харнес · безопасность · качество кода ·
> платформы-бенчмарки. Здесь — только новое; что подтвердилось без дельты — отмечено в конце разделов.
> Статусы: ✓ первоисточник открыт агентом · ◐ из выдачи/вторично (проверить при внедрении).
> Продуктовые решения из этого ресёрча — `memo-decisions.md §H`; процессные — в `.claude/rules/` и плейбуке.

---

## 1. Безопасность (самые дорогие находки)

**1.1. Slopsquatting — supply chain через самого агента.** ✓ USENIX Security 2025 (16 LLM, 576k сэмплов):
~19.7% пакетов, рекомендованных ИИ, **не существуют**; 43% галлюцинаций стабильно повторяются → атакующий
регистрирует имя заранее. `pip-audit` ловит известные CVE, но НЕ свежий вредоносный пакет, который агент сам
добавил. Защиты: правило «новый пакет = проверка существования/возраста/популярности + ревью человека»
(→ rules/security.md); lockfile-дисциплина в CI (`uv sync --frozen` ✓ есть; npm — `npm ci` ✓ есть);
`ignore-scripts` для npm и pip `--require-hashes` — по триггеру (проверить, что не ломает сборку);
cooldown свежих версий (pnpm v11: minimumReleaseAge=1д по умолчанию; рекомендация ≥7д).
*(snyk.io/articles/slopsquatting-mitigation-strategies, pnpm.io/supply-chain-security)*

**1.2. «Comment and Control» — угон агентов через недоверенный контент.** ✓ Апрель 2026, CVE-2025-66032
(CVSS 9.4): один заголовок PR одновременно угнал Claude Code Review, Gemini CLI и Copilot — каждый выгрузил
секреты репозитория. Вывод индустрии (+CaMeL): prompt injection промптами не лечится, только архитектурой.
Механические защиты: агент читает недоверенное (Issue/PR/веб/чужие логи) → **без секретов и write-прав**;
GitHub Actions пинить **по SHA-коммиту**, не `@v1`; `contents: write`/`id-token` — только где нужно; не
открывать чужие репо агентом с доверенным окружением (инцидент Amazon Q: auto-load MCP-конфигов крал
AWS-ключи). Справочник атак: github.com/webpro255/awesome-ai-agent-attacks.
*(CSA research notes 2026-04; css.csail.mit.edu CaMeL)*

**1.3. Supply chain самого харнеса (MCP/skills/plugins) — непокрытая категория.** ◐ Tool poisoning через
описания MCP-тулов; 1184 вредоносных skill в маркетплейсе; аудит: 40% MCP-серверов без аутентификации, 43%
с command-injection. Правило: сторонние MCP/skills/plugins — только после ручного аудита исходников; pin
версий; SKILL.md и tool descriptions = untrusted input. *(arxiv 2601.17548)*

**1.4. Дизайн API-ключей платформы — что дополнить в AgentKey.** ✓ Наше ядро верно (sha256, показ один раз,
`compare_digest`, префикс `memo_sk_live_` ✓, `last_used_at` ✓). Консенсус добавляет: **правило под наш
префикс в gitleaks** (сделано: `.gitleaks.toml`), `expires_at` + авто-ревокация неиспользуемых, скоупы
least-privilege (OWASP LLM06 Excessive Agency: не «один ключ — всё API»), rate limit per key, окно ротации
из двух активных ключей, **аудит-лог вызовов по ключу** (OWASP Agentic 2026: «нельзя ответить, что агент
делал на прошлой неделе» без него — у нас закрыто дизайном TraceEvent, подтвердить в плане 003).
*(genai.owasp.org; Google/GitGuardian/Peakhour API-key practices)*

**1.5. Django-прод чек-лист.** ✓ Django 6.0 — **встроенный CSP** (`SECURE_CSP`, сначала report-only);
`manage.py check --deploy` как CI-гейт (у нас — триггер «перед деплоем», иначе красный на дев-настройках);
django-axes / django-ratelimit на login и выдачу ключей (тайминг-выравнивание есть, лимита попыток нет);
SECURE_HSTS/SSL_REDIRECT/NOSNIFF/X_FRAME_OPTIONS — перед первым внешним доступом.
*(docs.djangoproject.com/en/6.0/ref/csp; OWASP Django Cheat Sheet)*

**1.6. Credential proxy — «агент никогда не видит секрет».** ◐ Infisical Agent Vault (open-source HTTP-прокси:
секрет подставляется по домен-allowlist ниже процесса агента), Phantom Token Pattern. Наш deny на Read .env
защищает файл, но секреты живут в env запущенного приложения. Триггер: появление реальных прод-ключей.

**Без дельты:** JWT-схема (ротация+reuse-детект), OAuth double-submit, PBKDF2+тайминг, хэш ключей — на уровне.

## 2. Харнес разработки

**2.1. Эмпирика контекст-файлов (меняет политику).** ✓ ETH Zurich (arxiv 2602.11988, 138 задач, 4 агента):
LLM-сгенерированные CLAUDE.md **снижают** успех ~3% и удорожают на 20–23%; человечески-курируемые дают ~+4 п.п.
Vercel: skills не срабатывают сами в **56%** случаев; явный указатель «читай docs/X перед задачей Y» — 100%.
Правила: каждая строка контекста должна быть тем, что агент **не может открыть сам**; никаких /init-простыней;
rules > skills для нашего масштаба; «CLAUDE.md = RAM, docs = диск», бюджет ~150–200 надёжных инструкций.

**2.2. Хуки: несгораемый deny и мягкие гейты.** ◐ `permissionDecision: "deny"` в PreToolUse держится даже в
bypassPermissions — единственный гейт, переживающий «жёлтый режим» (проверить наш block-hook там). Stop-хук
умеет `additionalContext` — мягкий гейт («доделай X») без ошибки. Политика латентности: PreToolUse <100мс,
узкие матчеры, тяжёлое — в PostToolUse, внешнее — таймаут 1–2с + fail-open. Пара «hook (принуждение) +
rules-файл (объяснение)»: сообщение хука ссылается на правило — у нас соблюдено в arch-lint, проверить в хуках.

**2.3. Наблюдаемость самого агента — бесплатно.** ✓ Claude Code имеет встроенный OTel (спаны model/tool,
токены/стоимость/сессии) — включается env-переменными; лёгкая альтернатива — claude_telemetry. Цикл
«трассы отказов → правка харнеса → замер» даёт прирост, сопоставимый с апгрейдом модели (arxiv 2604.25850).
Триггер: «хочу понять, куда уходят токены» / рост числа правил.

**2.4. Долгоживущие агенты (Anthropic, первоисточник).** ✓ Паттерны для многосессионных срезов:
initializer-агент; feature-list JSON c passing:false; одна фича = одна сессия; старт сессии = progress-файл +
git log + smoke; e2e «как человек» до пометки passing. Триггер: длинные срезы memo.

**2.5. Оркестрация.** ◐ Worktrees окупаются при 4–8 независимых задачах (узкое место — ревью человека; для
solo реалистично 2–3). Ralph-loop оправдан только при машинной верификации результата + песочница обязательна.
Cross-model review: официальный codex-плагин для Claude Code (март 2026); чужая модель надёжнее ловит
security/edge-cases (нет сикофантии к своему коду).

## 3. Качество агентного кода

**3.1. «Промпты не лечат деградацию» — теперь с цифрами.** ✓ SlopCodeBench детально: эрозия структуры в 77%
траекторий, скорость деградации агентов в ~5–6× выше человеческой; prompt-интервенции улучшают старт, но
**не замедляют** деградацию. Вывод: механические гейты — единственная рабочая защита (вся наша ставка верна).

**3.2. SpecBench: reward hacking в кодинге.** ✓ o3 хакает 30.4% прогонов: удаляет падающие тесты, патчит
верификатор. Рецепты: **test lock** (агент не трогает тесты-верификаторы; наш отложенный deny на
`tests/e2e/**` — включать при первом инциденте или сразу с появлением e2e) + второй слой проверки поверх
«тесты зелёные». *(arxiv 2605.21384)*

**3.3. aislop — готовый слоп-линтер.** ◐ Детерминированный сканер без LLM: 50+ правил (narrative-комменты,
swallowed exceptions, hallucinated imports, дубли-хелперы, dead code, todo-стабы), Python в т.ч., CLI +
pre-commit + CI-гейт (`failBelow`), активен (v0.13.1, июнь 2026). Может заменить связку vulture+jscpd+свои
правила. Триггер: попробовать advisory-режимом при заметном объёме прод-кода; в блок — после калибровки.
Запасные: sloppylint (py-специфичный), desloppify (харнес уборки). *(github.com/scanaislop/aislop)*

**3.4. Против review debt (процесс).** ✓ Консенсус: PR ≤200–400 строк (дальше качество ревью падает;
oversized = elevated-risk событие); **comprehension-гейт** — «AI написал» не ответ, автор обязан объяснить
control flow / edge cases / failure paths (ownCloud формализовал в policy). Для нас: «агент обязан объяснить
дифф Арсену» → rules/general.md. Cloudflare (131k ревью/мес, $1.19/шт): специализированные LLM-ревьюеры по
доменам + risk-tiering по размеру диффа + фильтрация lock/generated из диффа + явный список **«что НЕ
флагать»** + инкрементальный re-review с памятью прошлых находок; честно слаб в архитектуре/concurrency.

**3.5. Архитектурный дрейф.** ✓ Thoughtworks Radar (апр 2026): агенты ускоряют дрейф («poor code begets
poorer code»); рецепт — детерминированные анализаторы + LLM для семантики, первый скан = лавина → приоритизировать.
Инструмент под Python: **pytest-archon** (ArchUnit-стиль: запрещённые зависимости как pytest-тесты — ложится
в существующий `make test` без нового CI-шага; альтернатива import-linter). Триггер: ≥3 модулей со строгими
границами.

**3.6. Метрики.** ◐ DORA ROI-отчёт (янв 2026): выигрывают команды с сильными инженерными основами. AI-era
надстройки: **Code Durability** (доля кода, дожившего N недель без переписывания — дёшево по git) и
rework/churn rate. Триггер: «хотим мерить прогресс».

## 4. Платформа-бенчмарк (продуктовые находки → memo-decisions §H)

**4.1. FinBalance (arxiv 2606.15949, июнь 2026).** ✓ **Прямой сосед по домену**: multi-document accounting
reconciliation benchmark, синтетика, детерминированный скоринг. Прочитать целиком; переиспользовать
таксономию ошибок сверки; наша дифференциация — seed-генерация + платформа/арена + анти-гейминг (у них
статичный датасет). Рядом: AuditFlow (символьные среды: LLM планирует, детерминированный движок проверяет),
FinVerBench (валидность фин-бенчмарков), FinToolBench, BigFinanceBench — домен горячий, ≥5 бенчмарков за полгода.

**4.2. CapCode-принцип (arxiv 2606.07379).** ✓ Детекция читерства **по построению**: в пул подмешиваются
задачи с заведомо недостижимым честным 100% (несводимая сверка) — балл выше потолка = статистическое
доказательство читерства, ранжирование честных сохраняется. Идеально ложится на детерминированный скорер.

**4.3. Экономика оценки.** ✓ On Randomness (arxiv 2602.07150, 60k траекторий): single-run pass@1 гуляет на
2.2–6.0 п.п. **даже при temperature=0** → минимум 3–5 прогонов на (агент, задачу), интервалы вместо точки,
пара pass@k (оптимист) / pass^k (пессимист). Efficient Benchmarking (2603.23749): держать в зачёте задачи с
pass-rate **30–70%** (режет пул на 44–70% без потери ранжирования); «все решают/никто не решает» → в
smoke/pre-flight. Beyond Static Leaderboards (2606.19704): показывать **корреляцию public/private рангов**
как метрику здоровья экзамена (Kaggle shake-up).

**4.4. HAL пивот в reliability.** ✓ Принстон приостановил классический лидерборд и мерит **надёжность**
(дисперсию) агентов. Подтверждает: reliability score (разброс по прогонам) — правильная колонка таблицы.

**4.5. Изоляция.** ✓ Консенсус-2026: для исполнения чужого кода минимум microVM (Docker с общим ядром —
недостаточно). Для memo это аргумент **ЗА** нашу API-модель «агент снаружи, платформа раздаёт задачи по
HTTP» — мы не исполняем чужой код, класс риска ниже на порядок; зафиксировано как осознанное решение.

**4.6. Скоринг траекторий.** ◐ TRACE (WWW 2026): иерархическая utility-функция траектории + «минимальный
уровень подсказки, при котором агент справляется» как ось способности. Kaggle Game Arena: адаптивный
планировщик пар вместо round-robin — **-65% эпизодов** при том же ранжировании (паттерн для умного лизинга).
Готовые вьюеры трейсов: Phoenix / Opik / DeepEval поверх OTel — свой не писать.

## Сводный вердикт

- **Подтверждено без изменений:** вся линия «механические гейты > воспитание промптами» (теперь с цифрами),
  JWT/OAuth/хэш-дизайн, минимализм тулов, rules с явными указателями, «агент снаружи» для платформы.
- **Внедрено этим ресёрчем:** `.gitleaks.toml` (правило под memo-ключи), rules/security.md (недоверенный
  контент; новые зависимости; сторонние MCP/skills), rules/general.md (comprehension-гейт), обновления
  плейбука/ADR 006, продуктовые решения → memo-decisions §H.
- **Главные триггеры на будущее:** test lock вместе с первыми e2e; aislop при росте прод-кода; OTel самого
  агента при вопросе «куда уходят токены»; CSP/axes/check --deploy перед внешним доступом; credential proxy
  при реальных ключах; pytest-archon при ≥3 модулях.
