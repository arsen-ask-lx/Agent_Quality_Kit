# Хук агента правда срабатывает

**Намерение.** Человек заводит хук, чтобы машина держала то, что он держать не может: не дать
сделать `git push --force`, отформатировать после правки, не отпустить работу с красным
линтером. Ошибку в имени события Claude Code **не показывает** — хук просто никогда не
вызывается. Настройка выглядит как защита и защитой не является.

**Какой отказ это поймало.** Замер по 48 чужим настройкам `.claude/settings.json`, снятым с
GitHub 2026-09-07. Шесть настоящих находок в четырёх репозиториях:

```json
"PreToolCall": [
  { "matcher": "Bash(git commit*)",
    "command": "npm run typecheck && npm run test",
    "description": "Run typecheck and tests before committing to ensure CI checks will pass" }
]
```

События `PreToolCall` у Claude Code нет. Человек написал в описании, ради чего это стоит, — и не
запускается оно никогда. Такие же `PostToolCall` и `preToolCall` нашлись ещё в трёх проектах.

**Вторая половина записи — `matcher`, которого нет.** Документация дословно: *«If you add a
`matcher` field to an event without matcher support, it is silently ignored.»* События без
поддержки `matcher` — `UserPromptSubmit`, `PostToolBatch`, `Stop`, `TeammateIdle`, `TaskCreated`,
`TaskCompleted`, `WorktreeCreate`, `WorktreeRemove`, `MessageDisplay`, `CwdChanged`. Написав
`"Stop": [{ "matcher": "Bash" }]`, автор думает, что отобрал, а хук срабатывает на всём.

**Готовый аналог есть, и он этого не ловит — проверено прогоном.**
[`claudelint`](https://github.com/pdugan20/claudelint) (npm `claude-code-lint`, MIT, обновлялся
вчера) проверяет схему `settings.json`, синтаксис прав и ловит `"allow": ["*"]` — это мы не
дублируем, ставьте его рядом. В его исходниках есть и правило `hooks-invalid-event`, но живой
прогон версии 0.8.0 на файле с `"PoToolUse"` даёт «No problems found»: категория `hooks` на
`.claude/settings.json` не срабатывает. Причина найдена в их исходнике 2026-09-08 — правила
категории `Hooks` запускает только `HooksValidator` (`src/validators/hooks.ts`), а он ищет файлы
по единственному образцу `hooks/hooks.json` (`src/utils/filesystem/patterns.ts:45`). Сообщено:
[issue #217](https://github.com/pdugan20/claudelint/issues/217). [`cclint`](https://github.com/carlrannaberg/cclint)
последний раз трогали в сентябре 2025 и лицензии у него нет. `AgentLint` знает 12 событий из 33.

**Почему список, а не «похоже на опечатку».** Первая версия краснела только на близких промахах —
чтобы не объявить опечаткой событие, появившееся после нас. Замер эту конструкцию убил:
`PreToolCall` отстоит от `PreToolUse` на четыре правки, и проверка его пропускала. Правило,
красящее **всё** незнакомое, на 39 случайных чужих настройках дало **ноль** ложных.

Размен назван вслух: событие, добавленное в Claude Code после нас, эта проверка объявит
незнакомым. Такое ложное срабатывание видно, оно громкое и чинится одной строкой в списке.
Пропуск не виден никак — хук молчит, и молчание неотличимо от того, что всё хорошо. Из двух
ошибок выбираем шумную.

**Откуда список.** https://code.claude.com/docs/en/hooks — раздел Configuration, таблица
«Each event type matches on a different field» и заголовки разделов событий. Снято 2026-09-07,
33 события. Дата стоит в самой проверке: список устареет, и это должно быть видно.

**Чего НЕ ловит.**

- **Хук с верным именем, который падает или ничего не делает.** Проверяется только то, что он
  будет вызван, а не то, что он работает. Вызванный и сломанный хук — предмет другой записи.
- **Права.** `"allow": ["*"]`, слишком широкие разрешения, ошибки в синтаксисе правил — это
  `claudelint`, и он делает это лучше.
- **Команду хука, указывающую на несуществующий скрипт.** Искали и **не нашли материала**:
  шесть чужих репозиториев склонированы целиком, 30 путей к скриптам хуков проверены на диске,
  несуществующих — ноль. Это не «не искали»: выборка содержала предмет, и предмет оказался
  здоров. Запись не начата. У `claudelint` правило `hooks-missing-script` есть, но на
  `.claude/settings.json` оно, как и `hooks-invalid-event`, не срабатывает — проверено прогоном
  версии 0.8.0.
- **Хуки в плагинах и в `~/.claude/`.** Смотрим только настройки проекта: домашний каталог не
  лежит в репозитории и в дифе не виден.
- **`stop_hook_active`.** Хук на `Stop`, не проверяющий это поле, зациклится — но Claude Code
  сам обрывает его после восьми подряд блокировок, так что цена ошибки восемь ходов, а не
  вечность. Проверять содержимое скрипта на любом языке дороже, чем стоит.

**Образцы.** `red/` — опечатка (`PoToolUse`), чужое написание (`post_tool_use`), незнакомое имя
(`PreToolCall`) и `matcher` на `Stop`. `green/` — те же хуки с верными именами, `matcher: ""` и
`matcher: "*"` на событиях без поддержки matcher (они означают «всё» — ровно то, что и
происходит, автор не обманут).
