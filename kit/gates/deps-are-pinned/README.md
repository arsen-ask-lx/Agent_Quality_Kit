# Версии зависимостей закреплены

**Намерение.** Рядом с объявлением зависимостей лежит файл с точными версиями, и он в
репозитории.

**Какой отказ это поймало.** Обязательный минимум проекта требует точных версий всего, что
участвует в сборке. Проверки на это не стояло нигде.
Запись в журнале: `incidents/README.md`, 2026-08-27.

**Почему это важнее, чем кажется.** Без закреплённых версий среда разъезжается между машиной
разработчика, конвейером и сервером. Это класс ошибок, который **невозможно поймать тестами**:
тесты зелёные у всех, а падает у одного. «У меня работает» становится неопровержимым, потому что
сравнить нечего.

**Что именно проверяется.** Для каждого найденного объявления зависимостей — наличие
соответствующего файла с закреплёнными версиями. Для `requirements.txt` иначе: там закрепление
живёт в самом файле, поэтому проверяется, что версии указаны через `==`, а не «не ниже такой-то».

**Пустое объявление пропускается.** Проект без единой зависимости закреплять нечем: пакетный
менеджер не создаст файл версий там, где версий нет. Требовать его значило бы красить гейт на
пустом месте — а такой гейт выключают.

**Чего НЕ ловит.** Что файл свежий: он может быть от прошлого года и не совпадать с объявлением.
Это ловится командой пакетного менеджера, а не наличием файла. Из отказов конвейера соблюдать
файл ловится только явный у pnpm (`--no-frozen-lockfile`, `--frozen-lockfile=false`): у pnpm в CI
соблюдение включено по умолчанию, и отказ — это флаг. `npm install` вместо `npm ci` и
`yarn install --no-immutable` не проверяются: частоту их не мерили.

**Конвейер, выключивший lock-файл.** Файл версий в репозитории есть, а установка в конвейере
его игнорирует — тесты идут не на тех версиях, что закреплены. Найдено разбором `evalite`
(2026-09-26): флаг стоит во всех трёх конвейерах, включая выпуск. Замер: поиск GitHub даёт около
12 576 файлов конвейеров с флагом; из 20 проверенных руками в 20 он в команде установки при
`pnpm-lock.yaml` в корне. У `zizmor` из 41 проверки про lock-файл нет ни одной.

**Готового аналога нет** — ни в линтерах, ни в пакетных менеджерах: они
умеют создать файл версий, но не умеют требовать, чтобы он существовал и лежал в репозитории.

**Закрепляют не только poetry и uv.** Для `pyproject.toml` файлом закрепления считается и
`requirements.txt` — но только если он сам проходит проверку, то есть все версии в нём стоят
через `==`. Иначе «есть requirements.txt» стало бы способом обойти гейт пустым файлом.
Найдено замером по `httpx`: там инструменты закреплены до патча прямо в `requirements.txt`,
а гейт требовал ещё и `poetry.lock`, которого в этом укладе не бывает вовсе.

**Не различает библиотеку и приложение.** Библиотека намеренно оставляет
границы своих зависимостей широкими — закрепив их у себя, она ломает сборку всем, кто её
ставит. Гейт смотрит только на то, закреплено ли окружение самого проекта, и правильно молчит,
когда библиотека закрепила инструменты и не закрепила зависимости.

**Образцы.** `red/` — объявление зависимостей без закрепления (в обычном отформатированном виде:
до 2026-09-26 образец стоял в одну строку, и гейт не видел обычный `package.json`), плюс `pyproject.toml` рядом с
незакреплённым `requirements.txt`. `green/` — с закреплением, включая уклад «pyproject плюс
requirements.txt с точными версиями».
