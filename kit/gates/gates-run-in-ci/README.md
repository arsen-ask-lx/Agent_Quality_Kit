# Объявленный гейт запускается конвейером

**Намерение.** Проверка, которую гоняет только человек, работает ровно до первого «забыл».

**Какой отказ это поймало.** В `audit_project` часть проверок жила только в конвейере, а часть
только локально, и «прогнать всё как CI» означало десяток команд, которые надо помнить.
Итог одного дня: четыре красных круга по 15–18 минут, три из четырёх падений ловились локально
за секунды. Запись в журнале: `incidents/README.md`, 2026-08-25.

**Что именно проверяется.** Каждая команда из блока `gates:` манифеста упомянута в конфиге
конвейера — по пути к скрипту, если он есть, иначе по команде целиком.

**Прогон разом тоже считается.** Если конвейер запускает `aqk doctor --run`, он гоняет всё,
что объявлено в манифесте, и отдельный шаг на каждый гейт не нужен. Больше того, так лучше:
добавление гейта в манифест само добавляет его в конвейер, и они не расходятся.

**Чего НЕ ловит.** Что шаг конвейера действительно выполняется: он может стоять под условием,
которое никогда не наступает, или быть помечен необязательным. Упоминание — необходимое условие,
а не достаточное.

**Почему условий два.** Запись включается, только если есть и гейты, и конвейер. Нет конвейера —
сначала он: требовать «запусти гейты конвейером» там, где конвейера нет, значит показывать
человеку работу, которую он сделать не может.

**Готового аналога нет.** Проверено: `actionlint` и подобные проверяют синтаксис конфига
конвейера, а не то, что в нём запускается всё объявленное в вашем манифесте. Такой сверки нет ни
в одном известном инструменте — она возможна только там, где манифест существует.

**Образцы.** `red/` — гейт объявлен, конвейер его не упоминает. `green/` — упоминает.
