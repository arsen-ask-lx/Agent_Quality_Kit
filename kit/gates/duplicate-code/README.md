# Один и тот же код не размножается копиями

**Намерение.** Одинаковые куски не лежат в нескольких местах.

**Какой отказ это поймало.** В разборе 1069 коммитов: **число моделей захардкожено в четырёх
местах четырьмя разными значениями** — 10, 13, 14 и 30. Копии разъехались, и никто не заметил.
Запись в журнале: `incidents/README.md`, 2026-08-25.

**Почему это опаснее длины.** Правку вносят в одну копию из четырёх. Три остаются со старым
поведением, и расхождение всплывает не сразу и не там, где его сделали.

**Почему агенты плодят дубли особенно охотно.** Скопировать из соседнего файла дешевле, чем
найти общее место и вынести туда: копия точно работает, вынесение может что-то сломать.

**Готовый аналог есть, и под каждый стек свой.** `jscpd` для фронта — считает **похожесть**, а не
только точное совпадение. `pylint --enable=R0801` для Python — сравнивает разобранный код, и
переименованная переменная его не обманет. Рецепт под Python появился только 2026-09-07: до
ревизии каталога его не было вовсе, и питоновский проект получал нашу побайтовую самоделку,
хотя родной инструмент стоял у него уже установленным.

**Переносимая проверка грубее.** Она ищет одинаковые восемь строк подряд после снятия отступов —
совпадение байт в байт. Копия с переименованной переменной её не насторожит. Это запасной
вариант, а не замена.

**Одинаковые импорты — не дубль.** Окно, в котором нет ни одной строки кроме ввоза (`import`,
`use`, `require`, путь в кавычках внутри `import (…)` в Go) и одиноких скобок, находкой не
считается. Найдено замером по `cobra`: гейт краснел на `doc/man_docs.go` и `doc/md_docs.go`,
где совпадали восемь строк подряд из списка импортов и ни одной строки логики. В Go, Java и Rust
ввоз стоит по одной строке на строку, и в соседних файлах одного пакета он совпадает всегда.

**Тесты не проверяются.** Повтор в тестах часто осознанный: читаемость важнее сухости, и три
похожих теста лучше одного хитрого. Случай «три однотипных — свести в один с набором входов»
решается по правилам тестирования и глазами. На живом проекте **все двадцать находок были в
тестах** — гейт, который краснеет только на них, выключат целиком.

**Предел настраивается** переменной `AQK_DUP_LINES`, по умолчанию восемь строк.

**Триггер — от двадцати файлов.** В проекте на пять файлов дубли ищут глазами, и проверка была бы
шумом.

**Самая тяжёлая из наших.** На проекте в четыре тысячи файлов — порядка пятнадцати секунд:
она держит в памяти все восьмистрочные окна. Место такой проверки — перед пушем, в конвейере
или по расписанию, но не на каждый коммит.

**Чего НЕ ловит.** Копию с переименованной переменной, изменённым порядком строк или другим
форматированием — сравнение идёт байт в байт после снятия отступов. Не смотрит в тесты и в
сгенерированные файлы. Куски короче восьми строк не считает вовсе.

**Образцы.** `red/` — один блок в двух файлах. `green/` — блок вынесен в общую функцию.
