# Команды из свода существуют

**Намерение.** Агент берёт команды из свода дословно. Свод, который велит `npm run lint:cli`,
когда такого скрипта нет, отправляет агента в «Missing script» — и дальше тот либо чинит не то,
либо докладывает «проверил» про проверку, которой нет. Соседняя запись `entry-links-exist` ловит
в своде несуществующие ФАЙЛЫ; эта — КОМАНДЫ.

**Какой отказ это поймало.** Выборка 2026-09-11: 99 публичных репозиториев с `AGENTS.md`, где
упомянут `npm run`. В 9 свод называет скрипт, которого нет ни в одном `package.json`
репозитория. В двух история показывает механизм:

| Репозиторий | Что было | Что осталось |
|---|---|---|
| `notefig/notefig` | `lint:cli` добавлен в `cbb21a4c` вместе со строкой в своде, удалён в тот же день в `ffaf7d8c` | `npm run lint:cli` в `AGENTS.md` |
| `JonnyKreng/pebble-navi` | `debug` добавлен в `1630de8` вместе со строкой в своде, удалён через два дня в `757c563` | `npm run debug  # build + install + logs` |

Замер целиком — `incidents/README.md`, 2026-09-11.

**Почему машина, а не внимательность.** Скрипт удаляют в одном файле, свод живёт в другом, и
правка «fix(ci): resolve GitHub Actions failures» о своде не думает. Ровно как у
`entry-links-exist`: расхождение появляется не при написании свода, а через дни, в другой задаче.

**Что именно сверяется.**

| В своде | С чем |
|---|---|
| `npm run X`, `pnpm run X`, `yarn run X`, `bun run X` | ключи блока `"scripts"` всех `package.json` репозитория, кроме `node_modules` |
| `make X` (и `make -j4 X`) | цели всех `Makefile`, `makefile`, `GNUmakefile`, `*.mk` |
| `just X` | рецепты и псевдонимы `justfile` |

Скрипты берутся только из блока `"scripts"`: в `pebble-navi` `debug` — ещё и имя зависимости, и
поиск любого `"debug":` в файле сказал бы «есть». Все `package.json` репозитория, а не только
корневой: команда из свода часто живёт в пакете рабочего пространства.

**Какие файлы.** Только своды агента: `AGENTS.md`, `CLAUDE.md`, `GEMINI.md` в корне (регистр
имени не важен), `.claude/CLAUDE.md`, `.github/copilot-instructions.md`. README не берётся: там
пишут и команды для ЧУЖОГО проекта — «в своём проекте запусти `npm run aqk`».

**Готовый аналог.** agentlint, правило `cmd-cross-reference`, — только npm-скрипты и только
корневой `package.json`. На живом проекте, где свод называет шестнадцать целей `make` и ни
одного `npm run`, оно молчит по построению.

**Чего НЕ ловит.**

- **`make` и `just` в прозе.** Ищутся только внутри кода — в обратных кавычках и блоках: «make
  sure the tree is clean» — не команда. Свод, где команда написана прозой без кавычек, сверен не
  будет. `npm run` однозначен и ищется везде.
- **Шаблоны и присваивания.** `npm run build:*`, `npm run cms:<имя>`, `make <цель>`, `make test
  V=1` не называют одну команду и пропускаются. Отсюда же: свод, говорящий «скрипты `dev:local*`
  сняты», находкой не считается.
- **Команды с каталогом.** `make -C docs html`, `make -f other.mk x`, `npm --prefix web run x`,
  `pnpm --filter web run x` — цель живёт в чужом файле, по одной строке его не определить.
  Пропускаются целиком.
- **Сокращения и прочие запускалки.** `yarn build` без `run`, `tox -e lint`, `task lint`,
  `cargo xtask`, `uv run x` — не сверяются. Список взят из случаев, а не для полноты.
- **Цели из шаблонных правил make.** `%.o: %.c` покрывает `make foo.o`; такая цель будет названа
  несуществующей. В своде агента такое встречается редко.
- **Что команда делает то, что обещает свод.** Скрипт `lint` может ничего не проверять — это
  вопрос уже к нему, а не к своду.

**Образцы.** `red/` — свод велит `npm run debug`, а `debug` в `package.json` есть только в
зависимостях; и `make deploy` при `Makefile` с одной целью `test`: гейт обязан краснеть. `green/`
— те же имена существуют, `make -j4 lint` с флагом, `just fmt`, «make sure» в прозе, шаблоны
`npm run gen:*` и `make <target>`, `VERSION := 1.0` в `Makefile`: гейт обязан молчать.
