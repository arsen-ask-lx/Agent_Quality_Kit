# Подавление проверки — точечное и с причиной

**Намерение.** Когда проверка краснеет, у пишущего два выхода: починить код или заглушить
проверку. Второй дешевле и с виду неотличим от первого — конвейер зелёный, диф маленький.

Для агента это выход по умолчанию: задача сформулирована как «сделай, чтобы прошло», и
`@ts-ignore` решает её буквально. Дефект при этом остаётся, а сигнал о нём исчезает навсегда —
это тот же класс, что молчащий гейт, только оплаченный одной строкой.

**Какой отказ это поймало.** Замер по пятнадцати чужим репозиториям (20 774 файла): 22 находки,
19 настоящих. Среди них — `// @ts-nocheck` первой строкой боевой страницы в `kodus-ai`
(проверка типов выключена для целого файла), `# noqa E501` без двоеточия в `pr-agent`
(flake8 такую форму читает как безадресный `# noqa`: погашено не одно правило, а все),
`/** @ts-ignore */` и `.strict().argv // eslint-disable-line` без имени правила в `repolinter`.
Запись в журнале: `incidents/README.md`, 2026-09-06.

**Что именно проверяется.** Красным делается только **безадресное** подавление:

| Красное | Зелёное |
|---|---|
| `# noqa` | `# noqa: F401  — причина` |
| `# type: ignore` | `# type: ignore[no-any-return]` |
| `# flake8: noqa`, `# ruff: noqa`, `# mypy: ignore-errors`, `# pylint: disable=all` | точечная форма с кодом |
| `/* eslint-disable */`, `// eslint-disable-next-line` без правила | `// eslint-disable-next-line no-console -- причина` |
| `// @ts-ignore`, `// @ts-nocheck` | `// @ts-expect-error -- причина` |
| `#[allow(warnings)]`, `@SuppressWarnings("all")`, `//nolint`, `rubocop:disable all`, `shellcheck disable` без `=SC…` | те же с именем правила |
| `--no-verify` в скрипте или конфиге конвейера | обычный коммит |

`@ts-ignore` красный всегда — единственное исключение из правила «безадресное». У него есть
строго лучший брат: `@ts-expect-error` краснеет сам, как только становится не нужен, то есть
не переживает починку кода. `@ts-ignore` переживает и молчит дальше.

**Готовый аналог.** Есть, и под каждый язык свой:
[`eslint-plugin-eslint-comments`](https://github.com/mysticatea/eslint-plugin-eslint-comments)
с правилом `require-description` — для JavaScript и TypeScript;
[`flake8-noqa`](https://github.com/plinss/flake8-noqa) — для Python, он же ловит сломанную форму
`# noqa E501`. Если проект на одном языке — ставь их, они точнее: разбирают код, а не текст.
Эта запись нужна там, где языков несколько или где ставить нечего: она переносима, ничего не
требует установить и покрывает то, чего нет ни у одного из двоих — `@ts-ignore` как класс,
`--no-verify` в конвейере, `@SuppressWarnings("all")`.

**Чего НЕ ловит.**

- **Подавление внутри строкового литерала считается настоящим.** Фикстуры инструментов, которые
  сами обрабатывают подавления, дают ложные срабатывания: 3 из 22 на замере — тесты
  `react-doctor` и `ratchets`. Отличить строку от комментария надёжно можно только разбором
  языка, а его у переносимой проверки нет. Такие места — в `.aqkignore` или под храповик.
- **Точечное подавление без причины проходит.** `# noqa: E501` принимается, даже если рядом нет
  ни слова о том, зачем. Требовать объяснение от каждой строки значит получить гейт, который
  выключат целиком; за объяснением — к `require-description` из `eslint-plugin-eslint-comments`.
- **Не видит настройку в конфиге.** Правило, выключенное в `.eslintrc` или `pyproject.toml`, —
  такое же ослабление, но это уже не подавление в коде, а решение проекта, записанное явно.
- **Не знает, было ли подавление оправдано.** Проверка отвечает на вопрос «названо ли, что
  именно погашено», а не «стоило ли гасить».
