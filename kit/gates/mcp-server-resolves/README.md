# mcp-server-resolves

**Что ловит.** Объявленный MCP-сервер, которого на деле нет: команда указывает на несуществующий
файл, либо версия не закреплена и завтра приедет другая.

**Почему это отдельная запись.** Сервер, который не поднялся, агенту **никак не виден**: у него
просто нет этих инструментов, и он молча работает без них. Ни ошибки, ни строки в журнале.
Это тот же класс, что хук с опечаткой в имени события: настройка выглядит как возможность и
возможностью не является.

## Шишка, из которой она выросла

2026-09-08. В проект записали настройку `chrome-devtools-mcp` — выглядела безупречно:

```json
"chrome-devtools": { "command": "npx", "args": ["-y", "chrome-devtools-mcp@1.9.0"] }
```

Сервер был мёртв. Puppeteer подхватывал Windows-овый Chrome из `/mnt/c/` и падал с
`Target closed`. Узнали только потому, что запустили руками и прочитали журнал — обычно так не
делают: записали конфиг, увидели «сохранено», пошли дальше.

## Замер

Двадцать настоящих настроек `.mcp.json`, взятых поиском по GitHub 2026-09-08.

| | |
|---|---|
| конфигов проверено | 20 |
| покраснело | 9 |
| находок | 14 |
| ложных срабатываний | **0** |

Все находки — чужие серверы, которые тянутся незакреплёнными при каждом запуске:
`@modelcontextprotocol/server-github`, `firecrawl-mcp`, `mcp-server-postgres`, `@upstash/context7-mcp`.
Серверу с таким доступом «сегодня одна версия, завтра другая» — открытая дверь в цепочке поставок.

Замер тут же нашёл и два ложных срабатывания, оба починены до объявления записи рабочей:

1. `npx tsx rag/src/index.ts` — сервер **свой**, лежит в репозитории и уже под версией. Требовать
   закрепить `tsx` значит краснеть на нормальном укладе, а такой гейт выключают в первый день.
2. Починка первого съела настоящую находку: `@meridian/docs-mcp` — имя пакета со слэшем, а слэш
   считался признаком локального файла. Видно было только построчным сравнением до и после.

## Готовый аналог

Готового аналога нет. Проверено 2026-09-08 поиском: линтеры настроек агента существуют
(`claudelint`, `agent-lint`), но смотрят на права и хуки, а не на MCP. Ближайшее по смыслу —
наш собственный `deps-are-pinned`: там то же правило про версии, но для зависимостей сборки,
и файла `.mcp.json` он не видит.

## Чего НЕ ловит

- **Не запускает серверы.** Мёртвый по любой другой причине сервер — как в шишке выше, где путь
  и версия были верны, а падал сам браузер, — эта проверка не увидит. Запуск чужих команд на
  каждый коммит означает скачивание пакетов и минуты ожидания; такую проверку выключают сразу.
  Живое рукопожатие — то, что делают руками при подключении сервера, и это записано в методичке,
  а не в гейте.
- **Не судит об относительных путях.** `"command": "./bin/server"` не проверяется: рабочий
  каталог сервера задаётся полем `cwd`, и проверить существование без запуска нельзя.
- **Не знает, что пакет существует в реестре.** Это делает `no-phantom-package`, но только для
  того, что упомянуто в документации.
