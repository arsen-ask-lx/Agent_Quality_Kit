# Ошибка не глушится молча

**Намерение.** Перехваченная и выброшенная ошибка — это отказ, о котором никто не узнал.
Система продолжает работать «как будто всё хорошо», а причина всплывает через недели и в другом
месте. Ошибка либо обработана и записана, либо проброшена дальше.

**Своей проверки здесь больше нет — так решил замер.** Переносимая версия искала перехват по
тексту. Прогон по пяти чужим репозиториям (`httpx`, `fastapi`, `zod`, `cobra`, `ripgrep`) дал
46 находок, и настоящим оказался ровно один класс — пустые `catch (_) {}` в `zod`. Остальное:

```python
try:
    if sniffio.current_async_library() == "trio":
        return True
except ImportError:   # библиотеки нет — значит не trio. Это не глушение, это ветвление.
    pass
```

```rust
let _ = self.wtr.write(b"\n")?;   // «?» пробрасывает ошибку. Отброшено только число байт.
```

Питоновский `except <узкое исключение>: pass` — законный приём: ловят не ошибку, а её отсутствие.
Растовый `let _ = …?` вообще ничего не глушит. Отличить это от настоящего глушения можно только
разбором кода — а разбор уже написан.

**Готовый аналог — это и есть он сам.**

| Стек | Чем |
|---|---|
| Python | `ruff --select BLE,TRY400,SIM105` |
| JavaScript, TypeScript | `eslint no-empty` с `allowEmptyCatch: false` |
| Go | [`errcheck`](https://github.com/kisielk/errcheck) — канонический инструмент под этот предмет |

**Чего НЕ ловит.** Перехват, который что-то делает, но делает не то: `except: return None`,
`catch { return [] }`. Формально обработка есть, по сути ошибка потеряна так же. Это видно
только глазами и на ревью. Для Rust рецепта нет: у `clippy` есть близкие правила
(`let_underscore_must_use`), но мы их не замеряли, а рецепт без замера — та же догадка,
из-за которой эта запись и лишилась своей проверки.

**Чем это оплачено.** Проект на Rust, Java, Ruby, PHP по этому пункту не получает ничего.

**Образцы.** `red/loader.py` — `except Exception: pass`. `green/loader.py` — узкое исключение,
запись в журнал и проброс. Проверяются рецептом `python` (`samples_for`).
