# Код, который никто не вызывает, не остаётся в проекте

**Намерение.** Функции, классы и переменные без единого обращения удаляются, а не копятся.

**Какой отказ это поймало.** Ревизия гейтов в `audit_project`: **мёртвые функции бэкенда не искал
никто.** Импорты закрывал линтер, фронт закрывал `knip`, бэкенд был пуст. Первый же прогон дал
реестр на **148 записей**. Запись в журнале: `incidents/README.md`, 2026-08-27.

**Почему это про агентов особенно.** Агенты **не удаляют код** — обучение награждает за
написанное, не за удалённое. Отсюда мёртвые области, которые не ловит даже беглый взгляд: код
выглядит рабочим, он просто никому не нужен.

**Переносимой проверки здесь нет намеренно.** Чтобы понять, вызывают ли функцию, нужен граф
вызовов, а не поиск по тексту. Проверка на `grep` давала бы ложные срабатывания на каждом
динамическом вызове — и её выключили бы в первый день.

Это тот случай, когда без готового инструмента не обойтись. Под каждый распространённый стек он
есть: `vulture` для Python, `knip` для TypeScript и JavaScript, `staticcheck -checks U1000` для
Go, `dead_code` в clippy для Rust.

**Что это значит на практике.** На машине без нужного инструмента проверка каталога скажет
«не проверена — нужен один из: vulture, npx, staticcheck, cargo» и не выдаст её за рабочую.

**Чего НЕ ловит.** Динамические вызовы: то, что зовут по имени из строки, из настроек или через
отражение. Поэтому у `vulture` есть уровень уверенности, а находки читают глазами прежде, чем
удалять. Первый прогон такого инструмента — **лавина**, и разбирают её по частям, а не разом.

**Готовый аналог — это и есть он сам.** Своей проверки здесь не будет.

**Образцы.** `red/` — функция, которую никто не зовёт. `green/` — та же функция, вызванная.
