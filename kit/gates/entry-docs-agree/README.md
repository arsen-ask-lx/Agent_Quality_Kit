# Два свода агента не расходятся

## Какой отказ это ловит

`AGENTS.md` читают Codex, Cursor, Copilot и всё, что выросло вокруг этого соглашения;
`CLAUDE.md` читает Claude Code. Когда оба файла лежат в корне и пересказывают одно и то же
своими словами, правка попадает в один из них. Второй продолжает велеть старое — и агент,
который его прочитал, уверен, что прочитал свод проекта.

Настоящий случай, 2026-09-23, `0x3639/go-syrius`, один коммит:

| | AGENTS.md | CLAUDE.md |
|---|---|---|
| тулчейн | **Go 1.25.13** | **Go 1.26** |
| закреплённый SDK | `znn-sdk-go` v0.3.1 | `znn-sdk-go` v0.5.0 |

`go.mod` в репозитории один. Значит, один из двух сводов врёт про него любому агенту, который
его откроет, — и по выводу это ничем не отличается от правды.

## Замер, а не впечатление

300 чужих репозиториев со сводом агента, взятых поиском по коду (2026-09-23):

| | сколько |
|---|---|
| держат оба файла в корне | **85** |
| из них один свод уже называет другой (`@AGENTS.md`, ссылка, строка «правила там») | **58** |
| дословные копии | 5 |
| **краснеет эта проверка** | **4** |

Все четыре разобраны руками, ложных среди них нет:

- `0x3639/go-syrius` — таблица выше;
- `andrewck24/volleybro` — навыки вызываются `$spectra-*` в одном своде и `/spectra-*` в другом;
- `bwz96sco/or_llm_agent` — блок инструкций Trellis стоит только в `AGENTS.md`, и про команды
  `/trellis:*` Claude Code не узнает никогда;
- `amikos-tech/ami-gin` — в `CLAUDE.md` дописаны разделы про CI, стиль кода и CLI, в `AGENTS.md`
  их нет, при этом у `AGENTS.md` есть свои строки, которых нет у соседа.

Прогон повторён под `mawk` и `gawk` — 4 из 85 в обоих случаях, список тот же.

## Почему «почти одинаковы», а не «отличаются»

Это главное решение записи, и оно стоило двух чужих ошибок.

**Два разных документа — законная раскладка.** Короткий свод одному агенту, подробный другому:
17 репозиториев из 85 живут так, и обвинять их не в чем. Красное здесь — след **копии, которая
разъехалась**: общая половина строк доказывает общее происхождение, расхождение доказывает, что
копию не обновляли.

Обратное правило проверено на живых примерах и оба раза оказалось неверным:

1. **`duke5am/agents-md-check`, правило `AGL019`** (создан 2026-09-18, MIT, без зависимостей).
   Краснеет, когда сходство сводов **ниже** 55 %. Прогон на паре близнецов 2026-09-23:

   | близнец | что в нём | их вердикт |
   |---|---|---|
   | `CLAUDE.md` — одна строка `@AGENTS.md` | правильная раскладка | **HIGH AGL019**, «token overlap 2 %» |
   | почти копия, Go 1.25.13 против Go 1.26 | настоящее расхождение | молчит (сходство 87 %) |

   Их совет на первом случае — «make one file the source of truth and reduce the other to a
   pointer»: файл уже является указателем. Инструмент срабатывает на починке и молчит на дефекте.

2. **`modelcontextprotocol/inspector#2427`, 2026-09-18.** Человек сообщил о расхождении сводов по
   статическому чтению репозитория. Сопровождающий закрыл в тот же день: их `CLAUDE.md` — это
   строка `@./AGENTS.md`, «нечему расходиться», и добавил, что находка выглядит так, потому что
   `CLAUDE.md` не открывали.

Поэтому пара, где один свод называет другой, зелёная всегда и без разбора содержимого.

## Что считается разницей

Строки, а не смысл. Проверка сравнивает **множества строк** после трёх приведений:

- блоки кода (``` ```) выброшены — там примеры, а не правила;
- пробелы по краям срезаны, пустые строки не считаются;
- **имя самого агента схлопнуто**: «this file provides guidance to Claude Code» и «…to Codex» —
  один и тот же свод. Без этого послабления замер дал бы четыре ложных из шести: четыре пары из
  85 отличаются ровно заголовком и именем агента.

Порог — половина общих строк. Ниже половины проверка молчит: это разные документы, а не копия.

Дословные копии тоже зелёные. Они ещё не разошлись, а обвинять за то, что случится потом, — это
то самое «читает текст, а не конструкцию», за которое из каталога вылетели две записи (`SPEC.md`
§6).

**Чего НЕ ловит.** Противоречие между двумя сводами, написанными независимо: если общих строк
меньше половины, проверка молчит, даже когда один велит `npm test`, а другой `pnpm test`. Это
плата за то, чтобы не обвинять 17 репозиториев из 85, живущих с двумя разными документами
законно. Не ловит и расхождение свода с кодом — про это соседняя запись `entry-commands-exist`.
Не заглядывает ни в `.cursor/rules`, ни в `.github/copilot-instructions.md`: там раскладка другая,
и без замера по ней запись молчала бы наугад. Дословные копии зелёные — они ещё не разошлись.

## Готовый аналог

**Есть, и он решает обратную задачу.** `duke5am/agents-md-check` — `AGL019`, разобран выше
прогоном: краснеет на правильной раскладке, молчит на разъехавшейся копии. Письмо об этом —
`research/outreach/LOG.md`.

`AgentLint` (`agentlint.app`, 33 проверки) правила про пару сводов не имеет — проверено по списку
правил, разбор в `research/competitors/agentlint.md`.

`claudelint` и `agnix` читают настройки и хуки, не своды, — проверено по их каталогам правил.

Общих линтеров это не касается вовсе: `ruff`, `eslint` и `golangci-lint` читают код, а не
markdown в корне.

## Как починить

Оставить один свод источником правды, второй свести к строке-включению:

```
@AGENTS.md
```

Claude Code подставляет содержимое по этой строке. Так уже сделаны 58 из 85 чужих репозиториев с
двумя сводами — и так сделан этот репозиторий: `CLAUDE.md` в корне подключает `AGENTS.md`, а не
пересказывает его.
