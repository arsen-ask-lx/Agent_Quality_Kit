# Секреты не попадают в код

**Намерение.** Приватный ключ, токен доступа или ключ платёжной системы не должны существовать
в файлах репозитория — ни в коде, ни в примерах, ни в тестах.

**Почему машина, а не внимательность.** Секрет попадает в историю один раз и остаётся там
навсегда: переписать ветку можно, но копии уже у всех, кто её тянул. Поэтому проверка обязана
стоять до коммита, а не «иногда руками».

**Что именно ищется.** Приватные ключи в текстовом формате и опознаваемые по префиксу токены:
платёжные `sk_live_`/`pk_test_`, ключи доступа облака `AKIA…`, токены репозитория `ghp_…`,
токены мессенджера `xox…`.

**Чего НЕ ловит.** Пароль в виде обычной строки — у него нет опознаваемой формы. Если продукт
выдаёт **свои** ключи, им нужен собственный узнаваемый префикс: тогда сканер сможет их находить,
а без префикса ключ неотличим от любой другой строки.

**Готовый аналог есть и он сильнее.** `gitleaks` знает сотни форматов
токенов и умеет читать историю, а не только рабочее дерево. Наша проверка — запасная: она без
зависимостей и работает там, где ставить лишний бинарь не хотят.

**Образцы.** `red/` — файл настроек с ключом платёжной системы. `green/` — тот же файл, значение
берётся из окружения.
