# Конвейер не отдаёт чужому коду свои права и секреты

**Намерение.** Конвейер выполняется с правами репозитория и с доступом к его секретам. Три
способа отдать их постороннему живут не в коде, а в двадцати строках yaml:

- **подвижная метка вместо SHA.** `uses: some/action@v1` — это указатель, который владелец
  действия может перевести на другой код в любой момент, и он же перевёдется у всех, кто на
  метку сослался;
- **`pull_request_target` вместе с выкачиванием ветки автора PR.** Триггер даёт секреты
  основного репозитория, а код берётся у постороннего;
- **`permissions: write-all`** на весь рабочий поток вместо нужного права нужному заданию.

Ни одну из трёх обычная проверка кода не увидит: это не код, это настройка.

**Какой отказ это поймало.** Собственный. На момент заведения записи у комплекта было **13
находок высокой строгости и 5 средней**, среди них десять действий, закреплённых меткой вместо
SHA, `id-token: write` на уровне всего потока и пять вызовов `checkout`, оставляющих учётные
данные в `.git/config`.

**Почему порог именно такой.** Замер 2026-09-08 по шести настоящим репозиториям:

| проект | High | Medium |
|---|---|---|
| `express` | 0 | 0 |
| `flask` | 0 | 0 |
| `uv` | 0 | 0 |
| `httpx` | 4 | 4 |
| `gin` | 18 | 0 |
| `ripgrep` | 19 | 8 |

Половина держит ноль. Порог взят с тех, кто его держит, а не выдуман: он достижим, и это
доказано чужой практикой, а не нашим мнением.

**Готовый аналог есть, и мы его зовём.** [`zizmor`](https://github.com/zizmorcore/zizmor) (MIT,
6459 звёзд, статический разбор GitHub Actions). Его же гоняет `flask` отдельным заданием
конвейера. Своего разбора yaml мы не писали. Обёртка отвечает за порог (`--min-severity medium`)
и за то, чтобы «не проверено» не выдавалось за «чисто»: `--no-exit-codes` разводит «нашлись
находки» и «инструмент не отработал», а отсутствие итоговой строки в выводе даёт код 2.

**Образцы.** `red/` — рабочий поток с `pull_request_target`, выкачиванием ветки автора PR,
`permissions: write-all` и незакреплённым действием. `green/` — тот же поток на `pull_request`,
с правами только на чтение, действием по SHA и `persist-credentials: false`.

**Чего НЕ ловит.**

- **Только GitHub Actions.** GitLab CI, Jenkins, Buildkite не проверяются: zizmor их не читает.
- **Не выполняет конвейер.** Разбор статический: он видит опасный уклад, но не видит, что делает
  скрипт внутри `run:`. Скачивание и выполнение чужого кода строкой `curl … | sh` внутри шага —
  предмет другой проверки, и её у нас нет.
- **Не сторожит SHA после закрепления.** Закреплённое действие может оказаться заброшенным или
  уязвимым; «закреплено» и «безопасно» — разные утверждения. Обновление закреплённых SHA — работа
  для dependabot, а не для этой записи.
- **Точечное гашение с причиной остаётся возможным.** `# zizmor: ignore[правило] причина` снимает
  находку, и это осознанный уклад: наш собственный `gate-not-weakened` требует, чтобы подавление
  было точечным и с названной причиной, а не порогом на весь файл. Мы сами пользуемся этим дважды
  и обе причины написали вслух.
