# Пароли из .env не лежат в git

**Намерение.** Файл окружения с настоящими значениями, попав в git, раздаёт пароли и ключи
каждому, кто склонировал репозиторий, — и из истории их уже не вычистить: ключ считается
скомпрометированным, его остаётся только сменить.

**Почему не «любой `.env` в git — брак».** Так было бы проще, и так было бы неверно. Сверено по
первоисточникам 2026-09-11:

- dotenv: «Should I commit my `.env` file? No. Unless you encrypt it with dotenvx. Then we
  recommend you do» — зашифрованный файл коммитят намеренно;
- Next.js: «`.env.test` file should be included in your repository, but `.env.test.local`
  shouldn't, as `.env*.local` are intended to be ignored through `.gitignore`»;
- Vite: «`.env.*.local` files are local-only and can contain sensitive variables. You should add
  `*.local` to your `.gitignore`» — про обычный `.env` не сказано ничего, и во многих проектах
  его коммитят с публичными настройками.

Поэтому правил два:

1. **`.env.local` и `.env.*.local` в git — находка всегда.** Здесь все сходятся: «local» — только
   для этой машины, что бы в файле ни лежало.
2. **Остальные `.env*` в git — находка, если внутри ключ-секрет с настоящим значением:** имя
   содержит `PASSWORD`, `SECRET`, `TOKEN`, `API_KEY`, `PRIVATE_KEY`, `ACCESS_KEY`, `CREDENTIAL`,
   либо значение — адрес с паролем (`схема://пользователь:пароль@хост`).

**Значение секрета проверка не печатает.** Вывод гейта попадает в лог конвейера; напечатать
пароль значило бы завести вторую утечку ради сообщения о первой. Называются файл, строка, ключ.

**Готовый аналог — есть частично, и мы его замерили.** Закоммиченный `.env` с тремя секретами и
`.env.local` с токеном (2026-09-11):

| | пароль, придуманный человеком | случайная строка | ключ с форматом поставщика | `.env.local` |
|---|---|---|---|---|
| наш `secrets-not-in-code` | не видит | не видит | видит | не видит |
| `gitleaks` 8.30.1 | не видит | видит (по энтропии) | видит | не видит |
| [`detect-secrets`](https://github.com/Yelp/detect-secrets) 1.5.0 | видит | видит | видит | не видит |
| эта запись | видит | видит | видит, если имя ключа говорящее | видит |

`detect-secrets` сильнее нас во втором правиле: он читает имена ключей во всех файлах, а не
только в `.env`. Если он у вас уже стоит в pre-commit с файлом-базой — второе правило закрыто
им, первое остаётся за этой записью. Родным рецептом он не стал: в конвейере ему нужна база
(`.secrets.baseline`), а запись ставится одной командой.

**Чего НЕ ловит.**

- **Секрет под неговорящим именем.** `STRIPE=…`, `DB=…`, `X_CONF=…` — ключ не называет себя
  секретом. Такое ловит только сканер по формату значения (`secrets-not-in-code`, `gitleaks`).
- **Короткий пароль.** Значения короче восьми знаков пропускаются: `dev`, `x`, `1234` в `.env`
  для локального стенда встречаются куда чаще настоящих паролей такой длины.
- **Пароль, совпавший со значением по умолчанию.** `postgres`, `root`, `admin`, `guest`,
  `minioadmin` — стоят в каждом docker-compose для разработки, и считать их утечкой значит
  краснеть на каждом втором проекте. Если такой пароль стоит на проде, это другая беда.
- **Публичные переменные сборки.** `NEXT_PUBLIC_`, `VITE_`, `REACT_APP_`, `EXPO_PUBLIC_`,
  `NUXT_PUBLIC_`, `GATSBY_` уезжают в браузер по устройству — секретом они быть не могут.
- **Шаблоны и тестовые данные.** `.env.example`, `.env.sample`, `.env.template`, `.env.dist`,
  `.env.test`, а также каталоги `templates/`, `examples/`, `fixtures/`, `testdata/`.
- **`.env.local` в каталоге тестов и демо.** `tests/`, `test/`, `__tests__/`, `spec/`,
  `playgrounds/`, `demos/` — там это фикстура: библиотека показывает или проверяет, что умеет
  читать такой файл. Замер: оба ложных срабатывания были ровно такими. Пароль внутри тестового
  `.env` при этом ловится — утечка в тестах остаётся утечкой.
- **Историю.** Проверяется то, что лежит в git сейчас. Файл, удалённый из индекса, из истории не
  исчез — это лечится сменой ключа, а не проверкой.
- **Файл, который лежит на диске и в `.gitignore`.** Это норма, а не находка: проверка спрашивает
  git, а не диск. (Ошибка соседа, agentlint, ровно в этом: он проверяет диск и кричит
  «закоммичен» про файл из `.gitignore`.)

**Образцы.** Настоящего git внутри каталога комплекта взять неоткуда, поэтому образцы кладут
список отслеживаемых файлов в `.aqk-tracked`; в живом проекте его не бывает и спрашивается git.
`red/` — `.env` с человеческими паролями (без формата и энтропии — ровно то, что сканеры
пропускают) и `.env.local` в индексе. `green/` — `.env` с публичными переменными сборки,
заглушками, ссылками `${…}`, паролями по умолчанию для локального стенда; `.env.production`,
зашифрованный `dotenvx`; `.env.test` с тестовым паролем; `.env.local` в `tests/`; `.env` в
`tests/fixtures/` и `templates/`. На всём этом арбитр обязан молчать.
