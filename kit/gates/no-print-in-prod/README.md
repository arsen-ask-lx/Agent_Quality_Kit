# Отладочная печать не доезжает до прод-кода

**Намерение.** `print` и `console.log` не попадают в прод: они проходят мимо системы логов,
не имеют уровня и могут вынести наружу то, чего в выводе быть не должно.

**Своей проверки здесь больше нет — и это результат замера, а не вкуса.** Переносимая версия
искала конструкции печати по тексту. Прогон по пяти чужим репозиториям (`httpx`, `fastapi`,
`zod`, `cobra`, `ripgrep`) дал **434 находки, настоящих — ноль**:

| Где нашлось | Что это было на самом деле |
|---|---|
| `zod/packages/bench` — 231 | бенчмарки, где печать и есть предмет |
| `fastapi/docs_src` | примеры кода в документации |
| `httpx/_exceptions.py` | печать **внутри строки документации**, между ``` |
| `fastapi/cli.py` | вывод программы командной строки — это интерфейс |
| `httpx/tests` | тесты |

Отличить это от забытой отладки можно только разбором кода, а не поиском по тексту. Разбор
уже написан и поддерживается: `ruff` и `eslint`. Наш поиск по тексту не приближался к ним и не
мог приблизиться.

**Готовый аналог — это и есть он сам.** `ruff --select T20` для Python, правило `no-console`
в eslint для JavaScript и TypeScript. Триггер записи сужен ровно до этих трёх языков: показывать
её проекту на Go, которому мы не можем дать ни инструмента, ни своей проверки, — значит показывать
работу, которую человек сделать не сможет.

**Чего НЕ ловит.** Печать через обёртку — `myprint(x)`, свой хелпер — не видит ни один из двоих:
они знают конструкции языка, а не «вывод в поток». Печать из программы командной строки оба
считают нарушением, хотя там она законна; такие каталоги исключают настройкой самого
инструмента (`per-file-ignores` в `ruff`, `overrides` в eslint), а не нашим кодом.

**Чем это оплачено.** Проект на Go, Rust, Java, Ruby по этому пункту не получает ничего. Так
честнее: проверка, которая на живом коде ошибается в ста процентах случаев, не «лучше, чем
ничего» — она хуже. Её выключают целиком, а вместе с ней и те, что работают.

**Образцы.** `red/service.py` — модуль с отладочной печатью. `green/service.py` — тот же модуль
через систему логов. `green/legacy.py` — закомментированная печать, на которой арбитр обязан
молчать. Проверяются рецептом `python` (`samples_for`), потому что переносимого рецепта нет.
