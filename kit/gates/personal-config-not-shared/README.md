# Личное не раздаётся всему проекту

**Намерение.** `CLAUDE.local.md` и `.claude/settings.local.json` по устройству личные. Попав в
git, они становятся обязательными для всех — и при этом их никто не рецензирует, потому что
туда их никто и не звал.

**Дело не в опрятности.** Документация Claude Code, дословно:

> Within each directory, `CLAUDE.local.md` is appended after `CLAUDE.md`, so your personal notes
> are the last thing Claude reads at that level.

То есть личные заметки одного человека читаются **последними** и перекрывают общие правила
команды — молча, у каждого. С правами то же самое: разрешения, которые человек выдал себе,
достаются всем, кто склонировал репозиторий.

Оба файла документация прямо велит не коммитить:

> For private per-project preferences that shouldn't be checked into version control… Add
> `CLAUDE.local.md` to your `.gitignore` so it isn't committed.

> Claude Code keeps it out of git when it creates the file; if you create it by hand, add it to
> `.gitignore` yourself.

(`code.claude.com/docs/en/memory` и `/settings`, сверено 2026-09-07.)

**Какой отказ это поймало.** Замер по тринадцати чужим репозиториям: шесть настоящих находок в
пяти, ноль ложных на семи контрольных. Самая наглядная — `shacker/django-todo`:

```json
"allow": [
  "Read(//Users/shacker/**)",
  "Bash(/Users/shacker/dev/home/django-todo/.venv/bin/python -m pytest …)"
]
```

Домашний каталог автора и абсолютные пути с его машины раздаются всем, кто клонирует проект.
На чужой машине они не работают, а разрешение на чтение чужого домашнего каталога — работает.

**Готовый аналог есть, и он не роняет прогон.** У [`AgentLint`](https://github.com/0xmariowu/AgentLint)
есть проверка C5 «`CLAUDE.local.md` not in git». Прогнали живьём (`npx -p agentlint-ai agentlint
check`, 2026-09-07) на репозитории, где в git лежат и `CLAUDE.local.md`, и
`.claude/settings.local.json`: он выдал **61/100** и **код возврата 0**. Флага порога в его
README нет, `--help` вывода не дал. Это оценка, а не гейт: в конвейере такой прогон зелёный.
Разница ровно та, ради которой существует наш стандарт. `claudelint` этой проверки не имеет.

**Чего НЕ ловит.**

- **Файл, лежащий на диске и не отслеживаемый git.** Он и не должен ловиться: это норма.
- **Репозиторий-заготовку проекта.** Если в корне лежит `cookiecutter.json`, `copier.yml` или
  `.copier-answers.yml`, все файлы в нём — рыба для будущего проекта, а не чьи-то личные.
  Проверка молча пропускает такой репозиторий, назвав причину вслух. Найдено замером:
  в `Frojd/Wagtail-Pipit` обе находки были ровно такими, и обе ложные.
- **Заготовки по имени и по месту:** `*.example`, `*.template`, каталоги `templates/`,
  `examples/`, `samples/`, `fixtures/`, а также подстановки генератора `{{…}}` в пути.
- **Личный свод под чужим именем.** Файл, названный `CLAUDE.md`, но содержащий личные заметки,
  проверка не отличит: она смотрит на имя и на git, а не на смысл текста.
- **Файлы других агентов.** `.cursor/rules` и инструкции copilot своего «личного» уровня не
  имеют — проверять там нечего.

**Образцы.** Настоящего git внутри каталога комплекта взять неоткуда, поэтому образцы кладут
список отслеживаемых файлов в `.aqk-tracked`; в живом проекте такого файла не бывает и список
спрашивается у git. Имя с точкой намеренно: файл `TRACKED` в корне чужого проекта — вещь
возможная, и он молча подменял бы собой список git. `red/` — оба личных файла в индексе.
`green/` — заготовки по имени, по каталогу и с подстановкой генератора, плюс `settings.local.json`
в `.vscode/` и `node_modules/`, на которых арбитр обязан молчать: личным этот файл считается
только внутри `.claude/`.
