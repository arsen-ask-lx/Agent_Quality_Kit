# AQK — что мы делаем, зачем и где сейчас

> **Читать первым.** Этот файл отвечает на «что это, откуда взялось, где мы находимся и что
> дальше». Правила работы — в `AGENTS.md`. Описание для внешнего читателя — в `README.md`.
>
> Обновлено: **2026-09-02**. Формат: ✅ сделано и доказано · ⬜ решено, не сделано ·
> ❌ отсутствует вовсе.

---

## 1. Откуда это взялось

Есть работающий проект `audit_project` — Django + React, около года разработки, где код пишут
агенты, а человек владеет смыслом. За этот год там накопилось то, что дороже самого кода:

- **правила**, каждое из которых прослеживается до конкретного отказа;
- **гейты** — механические проверки, не пускающие брак дальше;
- **шишки** — понимание, что именно ломается, когда код пишет машина.

Начался новый проект на TypeScript — и выяснилось, что перенести всё это нечем. Копировать файлы
руками неправильно: половина привязана к Django и 1С, а мёртвое правило хуже отсутствующего.

**AQK — ответ на этот вопрос.** Способ перенести не файлы, а сложившуюся практику.

## 2. Что это такое

Две вещи в одном репозитории, и их важно не путать.

**Стандарт** — соглашение о том, как репозиторий сообщает о своей готовности к работе агентов.
Один машиночитаемый файл `.aqk.yml` и четыре ступени соответствия.

**Эталонная реализация** — программа `aqk`, которая раскладывает комплект и считает уровень.
Реализация не есть стандарт: любой волен написать свою.

### Проблема, которую решает стандарт

По репозиторию нельзя машинно узнать: где правила, какие проверки обязательны, чем доказана
корректность, на чём здесь уже обжигались. Это нужно **четырём независимым сторонам** —
инструменту агента, конвейеру, новому человеку, аудитору. Там, где сторон несколько, нужен
стандарт, а не библиотека.

### Четыре ступени

| Уровень | Требуется | Проверяется |
|---|---|---|
| **AQK-0** | манифест и точка входа | `.aqk.yml` разбирается, файлы из `entry` существуют |
| **AQK-1** | правила и гейты командами | каталог `rules` есть, хотя бы один гейт непустой |
| **AQK-2** | образцы гейтов, храповик долга | каталоги `samples` и `ratchets` существуют |
| **AQK-3** | журнал уроков | `lessons` указывает на существующий путь или адрес |

## 3. Где мы сейчас

### ✅ Сделано и доказано

| Что | Чем доказано |
|---|---|
| комплект ставится одной командой в любой проект | прогон `npx github:…` с GitHub в чистую папку |
| не привязан к инструменту | `AGENTS.md` — обычный markdown; плагин Claude Code удалён намеренно |
| `init` безопасен при повторе | ничего не перезаписал, проверено в том числе из-под Windows |
| `doctor` считает уровень | ступени поднимаются по мере заполнения манифеста, проверено вручную |
| порог для конвейера работает | `--min 2` при уровне 1 → код возврата 1; `--min 1` → 0 |
| журнал не принимает брак | запись без раздела «Вывод» отклонена с кодом 1 |
| журнал не пустой | 9 настоящих уроков из `audit_project`, каждый с ценой и выводом |

### ⬜ Решено, не сделано

- **шаблоны гейтов в `gates/`** — каталог пуст намеренно: шаблон появляется, когда гейт поймал
  настоящий брак в живом проекте, а не придуман заранее;
- **храповик долга** — первый кандидат в `gates/`, механика описана, кода нет;
- **хуки** — запрет необратимых команд, автоформат после правки. Есть в `audit_project`, требуют
  отвязки от Python;
- **скиллы процесса** под TypeScript: план, ревью, красный тест;
- **измерить уровень своих проектов** — `audit_project` и Amplifie ещё не прогнаны.

### ❌ Отсутствует вовсе

- **тестов нет** — проверка ручная, прогоном на чистой папке. Для инструмента, который ставят
  в чужие проекты, это долг, а не решение;
- **конвейера нет** — ничто не мешает запушить сломанный `cli/index.mjs`;
- **второго пользователя нет** — значит все утверждения про стандарт пока непроверены практикой.
  Пока пользуется один человек, AQK — это личный набор с амбициозным названием.

## 4. Порядок, в котором это делается

⚠️ **Стандарт нельзя выпустить первым.** Спецификация раньше практики — тридцать первый
заброшенный репозиторий с манифестом и нулём пользователей. Правильный порядок обратный:

| # | Шаг | Состояние |
|---|---|---|
| 1 | живём по этому на двух своих проектах | ⬜ комплект разложен в Amplifie, уровень не измерен |
| 2 | `doctor` считает уровень | ✅ сделано |
| 3 | записываем сложившееся как короткую спецификацию | ⬜ пока живёт в `README.md` |
| 4 | третий проект — **чужой** | ❌ первый честный сигнал, его ещё нет |
| 5 | значок, сайт, разговор с людьми | ❌ только после четвёртого шага |

## 5. Очередь работ

По убыванию отношения пользы к цене:

1. **Измерить уровень `audit_project` и Amplifie.** Первое применение стандарта к себе. Ожидание:
   `audit_project` сядет на AQK-1, а не 2–3 — и это будет полезнее любой спецификации.
2. **Первый шаблон гейта — храповик долга.** Механика проверена в `audit_project` на четырёх
   реестрах; перенести и снабдить красным и зелёным образцами.
3. **Тесты на сам CLI.** Хотя бы: `init` идемпотентен, `doctor` считает ступени, `note` отклоняет
   запись без вывода. Сейчас это проверяется руками и держится на честном слове.
4. **Конвейер** — прогон тех же проверок на чужой машине.
5. **Хуки и скиллы процесса** — из трения, а не вперёд.

## 6. Правила, которые нельзя нарушать

- **если утверждение не проверяется машиной — его в стандарте нет**;
- **ступень не добавляется без кода, который её считает**;
- **стандарт описывает то, что мы уже делаем**, а не то, что задумали;
- **зависимостей у CLI нет** — программу должно быть можно прочитать глазами за один присест;
- **раздувание = смерть**: десятый пункт «для полноты» убивает стандарт.

## 7. Честный риск

Если идея хорошая, через год похожее выпустит кто-то крупный, и его версия победит по
дистрибуции. Защита одна: **быть первым, кто описал сложившуюся практику**, и держать реализацию
лучшей. Не гнаться за объёмом спецификации — гнаться за тем, чтобы ею было удобно пользоваться.
