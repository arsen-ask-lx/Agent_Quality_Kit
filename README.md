# temper

Оснастка для разработки с агентами: **скиллы, хуки и шаблоны гейтов** — плюс **общий журнал
шишек**, который копится из всех проектов сразу.

> **Зачем.** Каждый новый проект начинался с нуля: те же грабли, те же забытые проверки, те же
> заново переоткрытые решения. `temper` — то, что переносится между проектами одной командой, и то,
> куда возвращается опыт.

---

## Установка — способ для всех

Один способ на всё. Работает с любым инструментом — Claude Code, Codex, Cursor — и без ИИ тоже.
Нужен только Node 18+.

```bash
npx github:arsen-ask-lx/temper init
```

Разложит в проект:

| Что | Зачем |
|---|---|
| `AGENTS.md` | точка входа для агентов: железные правила, где что лежит, команды проекта |
| `CLAUDE.md` | точка входа для Claude Code — ссылается на тот же `AGENTS.md` |
| `.temper/rules/` | стандарты: общие, тесты, безопасность |
| `.temper/references/` | методички: минимум проекта, харнес, процесс, исследования |

Повторный запуск **ничего не перезаписывает** — только дополняет недостающее. Перезаписать
намеренно: `temper init --force`.

Проверить, что разложено и чего не хватает:

```bash
npx github:arsen-ask-lx/temper doctor
```

> **Один свод правил, несколько входов.** `AGENTS.md` читают Codex и другие, `CLAUDE.md` —
> Claude Code, и оба ведут в `.temper/`. Два расходящихся свода правил через месяц врут
> по-разному, и никто не знает, какой настоящий.

## Три идеи, ради которых это существует

**1. Гейт стережёт существующий артефакт.** Проверка, поставленная на код, которого ещё нет, —
мёртвое правило: молчит всегда, даёт ложное чувство защищённости и учит агента, что правила тут
бывают неприменимыми. После этого игнорировать начинают и живые.

**2. У гейта два образца, а не один.** Красный — код, где он обязан краснеть. **Зелёный** — код,
где обязан молчать. Без зелёного гейт однажды покраснеет на правильном коде, и его начнут
обходить вместе со всеми остальными.

**3. Храповик вместо большой чистки.** Правило вводится в проект, где старый код ему не
соответствует, так: файл со списком текущих нарушений, гейт разрешает список **укорачивать** и
запрещает **удлинять**. Правило действует со дня установки, старый код трогать не надо.
Проверка, что это храповик: «может ли новый код добавить нарушение и пройти?»

Подробности и остальное — `references/agent-harness-playbook.md`.

## Запись урока из другого проекта

Один раз:

```bash
git clone https://github.com/arsen-ask-lx/temper.git ~/projects/temper
```

Дальше — из любого проекта, не выходя из него:

```bash
temper note "гейт краснел на правильном коде"
```

Команда сама допишет запись, закоммитит и запушит. **Запись без раздела «Вывод» не принимается:**
урок без вывода — это история, а не урок.

---

## Как это должно расти

Комплект устаревает, если течёт только в одну сторону. Петля замыкается так:

```
момо → новый проект → там обожглись → temper note → урок вернулся в момо → достался следующему
```

Поэтому журнал и оснастка лежат в одном репозитории: они и есть две стороны одного механизма.
