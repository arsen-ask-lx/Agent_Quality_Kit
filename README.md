# AQK — Agent Quality Kit

**Стандарт готовности репозитория к тому, что код в нём пишет агент** — и его эталонная
реализация.

```bash
npx github:arsen-ask-lx/Agent_Quality_Kit init      # разложить комплект
npx github:arsen-ask-lx/Agent_Quality_Kit doctor    # уровень AQK и чего не хватает до следующего
```

Нужен только Node 18+. Работает с Claude Code, Codex, Cursor — и без ИИ тоже.

---

## Зачем стандарт

Сегодня по репозиторию **нельзя машинно узнать**, готов ли он к работе агентов: где правила,
какие проверки обязательны, чем доказана корректность, на чём здесь уже обжигались.

Это касается не одного человека, а четырёх независимых сторон — и потому решается стандартом,
а не библиотекой:

| Кто | Что хочет узнать |
|---|---|
| инструмент агента | что читать, что запускать, чего не трогать |
| конвейер сборки | какие проверки обязательны, что блокирует слияние |
| человек, пришедший в проект | по каким правилам тут живут |
| аудитор, служба безопасности | как в компании управляется код, написанный машиной |

## Один машиночитаемый файл

Весь стандарт — это `.aqk.yml` в корне репозитория:

```yaml
aqk: 1

entry:  [AGENTS.md]        # что агент читает первым
rules:  .aqk/rules         # где стандарты
gates:                     # что обязано пройти — командами, не словами
  lint:  npm run lint
  test:  npm test
  types: npm run typecheck
samples:  gates/samples    # красные и зелёные образцы гейтов
ratchets: gates/debt       # реестры долга, которые могут только укорачиваться
lessons:  https://…        # где копятся уроки
```

Всё остальное человекочитаемо. **Если утверждение нельзя проверить машиной, его в стандарте
нет:** иначе значок в README означает лишь доверие к автору.

## Четыре ступени

Лестница, а не «да/нет». Без ступеней никто не начинает: до полного соответствия далеко.

| Уровень | Что требуется | Что это даёт |
|---|---|---|
| **AQK-0** | манифест и точка входа для агента | любой инструмент понимает, что читать |
| **AQK-1** | правила на месте, гейты объявлены **командами** | проверки исполняются, а не описаны |
| **AQK-2** | у гейтов есть красные и зелёные образцы; долг под храповиком | гейт доказал, что ловит брак и молчит на исправном коде |
| **AQK-3** | журнал уроков ведётся, каждый инцидент даёт вывод | проект учится: одна шишка не набивается дважды |

Уровень считает `aqk doctor`. В конвейере — порогом:

```bash
aqk doctor --min 1     # выходит с ошибкой, если репозиторий ниже AQK-1
```

## Три идеи, на которых стоит стандарт

**1. Гейт стережёт существующий артефакт.** Проверка, поставленная на код, которого ещё нет, —
мёртвое правило: молчит всегда, даёт ложное чувство защищённости и учит агента, что правила тут
бывают неприменимыми. После этого игнорируются и живые.

**2. У гейта два образца, а не один.** Красный — код, где он обязан краснеть. **Зелёный** — код,
где обязан молчать. Без зелёного гейт однажды покраснеет на правильном коде, и его начнут
обходить вместе со всеми остальными. Это не гипотеза: так и произошло — проверка ругалась ровно
на то написание, которое сама предписывала.

**3. Храповик вместо большой чистки.** Правило вводится в проект, где старый код ему не
соответствует, так: файл со списком текущих нарушений, гейт разрешает список **укорачивать** и
запрещает **удлинять**. Правило действует со дня установки, старый код трогать не надо.
Проверка, что это храповик: «может ли новый код добавить нарушение и пройти?»

## Что кладёт `init`

| Путь | Что это |
|---|---|
| `.aqk.yml` | манифест — единственный машиночитаемый файл |
| `AGENTS.md` | точка входа для агентов: правила, где что лежит, команды проекта |
| `CLAUDE.md` | точка входа для Claude Code — ведёт в тот же `AGENTS.md` |
| `.aqk/rules/` | стандарты: общие, тесты, безопасность |
| `.aqk/guides/` | процедуры: как развернуть харнес, как записать урок |
| `.aqk/references/` | методички: минимум проекта, харнес дня 0, процесс, исследования |

Повторный запуск **ничего не перезаписывает** — только дополняет. Намеренно перезаписать:
`aqk init --force`.

> **Один свод правил, несколько входов.** `AGENTS.md` читают Codex и другие, `CLAUDE.md` —
> Claude Code, оба ведут в `.aqk/`. Два расходящихся свода через месяц врут по-разному, и никто
> не знает, какой настоящий.

## Журнал шишек

```bash
git clone https://github.com/arsen-ask-lx/Agent_Quality_Kit.git ~/projects/aqk   # один раз

aqk note "гейт краснел на правильном коде" <<'EOF'
**Класс:** гейт соврал
**Что случилось.** …
**Чем это стоило.** …
**Вывод.** 🔧 …
EOF
```

Пишется **из любого проекта**, не выходя из него. Запись без раздела «Вывод» не принимается:
урок без вывода — это история, а не урок.

## Честно о состоянии

Это **версия 1 стандарта с одним автором и двумя проектами**. Категорию нельзя объявить — её
можно только ввести в оборот. Пока комплектом пользуется один человек, `AQK` — красивое слово
в README; он начнёт работать, когда появится второй проект, поставивший его, и третий, сделавший
**свою** реализацию и назвавший её AQK-совместимой.

Правило развития одно: **если пункт не проверяется машиной, он в стандарт не входит.** Как только
захочется добавить десятый пункт «для полноты» — стандарт умер.

Опыт, из которого это выросло: Django + React проект, около года работы с агентами. Записи в
`lessons/` — не примеры формата, а настоящие шишки, каждая стоила времени.
