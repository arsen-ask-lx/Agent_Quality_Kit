# espada

Оснастка для разработки с агентами: **скиллы, хуки и шаблоны гейтов** — плюс **общий журнал
шишек**, который копится из всех проектов сразу.

> **Зачем.** Каждый новый проект начинался с нуля: те же грабли, те же забытые проверки, те же
> заново переоткрытые решения. `espada` — то, что переносится между проектами одной командой, и то,
> куда возвращается опыт.

---

## Установка — способ для всех

Работает с любым инструментом: Claude Code, Codex, Cursor, или вообще без ИИ. Нужен только Node 18+.

```bash
npx github:arsen-ask-lx/espada init
```

Разложит в проект:

| Что | Зачем |
|---|---|
| `AGENTS.md` | точка входа для агентов: железные правила, где что лежит, команды проекта |
| `CLAUDE.md` | точка входа для Claude Code — ссылается на тот же `AGENTS.md` |
| `.espada/rules/` | стандарты: общие, тесты, безопасность |
| `.espada/references/` | методички: минимум проекта, харнес, процесс, исследования |

Повторный запуск **ничего не перезаписывает** — только дополняет недостающее. Перезаписать
намеренно: `espada init --force`.

Проверить, что разложено и чего не хватает:

```bash
npx github:arsen-ask-lx/espada doctor
```

> **Один свод правил, несколько входов.** `AGENTS.md` читают Codex и другие, `CLAUDE.md` —
> Claude Code, и оба ведут в `.espada/`. Два расходящихся свода правил через месяц врут
> по-разному, и никто не знает, какой настоящий.

## Дополнительно: плагин Claude Code

Поверх комплекта, только для Claude Code, — два скилла и команда записи урока:

```
/plugin marketplace add arsen-ask-lx/espada
/plugin install espada@espada
```

Это надстройка, а не основной способ: всё главное ставится через `npx` и от инструмента не зависит.

## Что внутри репозитория

| Путь | Что это |
|---|---|
| `plugins/espada/skills/bootstrap-harness/` | развернуть харнес в проекте: пройти по обязательному минимуму, найти дыры, предложить **один** следующий шаг |
| `plugins/espada/skills/lesson/` | записать шишку в общий журнал — что случилось, чем стоило, что из этого сделано |
| `plugins/espada/bin/espada` | команда записи урока **из любого проекта**, без переключения репозитория |
| `plugins/espada/references/` | агностичный корпус: минимум проекта, методичка дня 0, процесс, каталог чужих приёмов, исследования |
| `lessons/README.md` | сам журнал шишек |
| `gates/` | шаблоны гейтов (пока пусто — заполняется из реальной работы, а не заранее) |

## Три идеи, ради которых это существует

**1. Гейт стережёт существующий артефакт.** Проверка, поставленная на код, которого ещё нет, —
мёртвое правило: молчит всегда, даёт ложное чувство защищённости и учит агента, что правила тут
бывают неприменимыми. После этого игнорировать начинают и живые.

**2. У гейта два образца, а не один.** Красный — код, где он обязан краснеть. **Зелёный** — код,
где обязан молчать. Без зелёного гейт однажды покраснеет на правильном коде, и его начнут
обходить вместе со всеми остальными.

**3. Храповик вместо большой чистки.** Правило вводится в проект, где старый код ему не
соответствует, так: файл со списком текущих нарушений, гейт разрешает список **укорачивать** и
запрещает **удлинять**. Правило действует со дня установки, старый код трогать не надо.
Проверка, что это храповик: «может ли новый код добавить нарушение и пройти?»

Подробности и остальное — `plugins/espada/references/agent-harness-playbook.md`.

## Запись урока из другого проекта

Один раз:

```bash
git clone https://github.com/arsen-ask-lx/espada.git ~/projects/espada
```

Дальше — из любого проекта, не выходя из него:

```bash
espada note "гейт краснел на правильном коде"
```

Команда сама допишет запись, закоммитит и запушит. **Запись без раздела «Вывод» не принимается:**
урок без вывода — это история, а не урок.

---

## Как это должно расти

Комплект устаревает, если течёт только в одну сторону. Петля замыкается так:

```
момо → новый проект → там обожглись → espada note → урок вернулся в момо → достался следующему
```

Поэтому журнал и оснастка лежат в одном репозитории: они и есть две стороны одного механизма.

## Откуда это взялось

Перенесено из проекта `audit_project` (Django + React, около года работы с агентами). Записи в
журнале — не примеры формата, а настоящие шишки: каждая стоила времени.

Что **не** перенесено намеренно: всё, что привязано к Django, PostgreSQL, Celery, 1С, Nextcloud.
Мёртвое правило хуже отсутствующего.
