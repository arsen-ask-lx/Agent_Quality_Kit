# AGENTS.md — работа над самим AQK

> Это точка входа для агента, работающего **над комплектом**, а не над проектом-получателем.
> Что это за проект, где мы сейчас и что дальше — в `README.md`. Здесь только правила работы.

## Железные правила

- **План до кода.** Нетривиальная задача начинается с плана, одобренного словами.
- **Красный тест до кода.** Сначала проверка, которая падает.
- **Максимум 3 попытки.** Не решил за три — стоп и человеку.
- **Готово = доказано.** Назови арбитра: прогон, живая проверка, сверка. «Выглядит рабочим» —
  не готово.
- **Развилка — вопрос человеку**, а не комментарий в коде.
- **Зависимостей у CLI нет и не будет.** Инструмент, который ставят одной командой в чужой
  проект, обязан читаться глазами за один присест. Каждая библиотека — лишняя дверь в цепочке
  поставок и лишний узел надёжности.

## Правила самого стандарта

- **Если утверждение не проверяется машиной — его в стандарте нет.** Иначе уровень означает
  доверие к автору, а не факт.
- **Ступень не добавляется без проверки.** Сначала код, который её считает, потом строка в
  таблице.
- **Стандарт описывает то, что мы уже делаем.** Всё, чего мы сами не соблюдаем, из него вылетает.
- **Раздувание = смерть.** Появилось желание добавить десятый пункт «для полноты» — не добавлять.

## Где что лежит

- `PROJECT.md` — что строим, для кого, что сделано и что осталось. **Начинать отсюда.**
- `README.md` — что это и как поставить, для постороннего
- `CHANGELOG.md` — что изменилось между версиями, формат Keep a Changelog
- `SECURITY.md` — куда сообщать об уязвимости (GitHub Security Advisories, не публичный Issue)
- `SPEC.md` — сам стандарт отдельно от нашей реализации: ступени, манифест, приёмка записи
- `tool/program.mjs` — точка входа: справка и диспетчер команд
- `tool/lib/` — общее: `core.mjs` (пути, вывод), `manifest.mjs` (`.aqk.yml` и ступени),
  `repo.mjs` (осмотр репозитория, триггеры, рецепты, сверка по намерению), `templates.mjs`
- `tool/commands/` — команды: `project.mjs` (`init`, `start`, `note`, `blob`), `doctor.mjs`,
  `gates.mjs` (`add`, `new`, `ratchet`, `find`, `why`)
- `kit/rules/` — правила текстом (переносятся в проекты как `.aqk/rules/`)
- `kit/docs/` — методички (переносятся как `.aqk/docs/`)
- `kit/gates/` — гейты: один гейт = одна папка с командой и образцами. Норма — `kit/gates/README.md`
- `incidents/README.md` — журнал шишек, общий на все проекты
- `tool/selfcheck/` — проверки самого комплекта: `syntax.sh` (все исходники разбираются),
  `units.mjs` (функции), `smoke.sh` (прогон на чистой папке), `gates.sh` (записи каталога),
  `conditional.sh` (доказательства)
- `.github/workflows/ci.yml` — те же проверки на чужой машине при каждом пуше
- `.github/workflows/triage.yml` — разбор входящих issue/PR: Claude Code по подписке решает,
  похоже ли на настоящий баг, и шлёт вердикт в Telegram. Прав на запись в GitHub не выдано —
  это не публичное действие от имени проекта

## Команды

- проверить синтаксис всех исходников: `bash tool/selfcheck/syntax.sh`
- прогнать на чистой папке: `T=$(mktemp -d) && cd "$T" && git init -q . && node <путь>/tool/program.mjs init && node <путь>/tool/program.mjs doctor`
- уровень этого репозитория: `node tool/program.mjs doctor`
- собрать методички одним файлом: `node tool/program.mjs blob` → `GOD_AI.md`
- проверить функции программы: `node --test tool/selfcheck/units.mjs`
- проверить комплект: `bash tool/selfcheck/smoke.sh`
- проверить гейты: `bash tool/selfcheck/gates.sh`
- порог для конвейера: `node tool/program.mjs doctor --min 1`

## Чего в этом проекте нет

- нет второго пользователя — значит все утверждения о стандарте пока непроверены практикой;
- модульными проверками покрыты только чистые функции: разбор манифеста, триггер, выбор рецепта,
  дедупликация, дописывание гейта. Команды, которые пишут на диск, проверяются прогоном на чистой
  папке — и то, что в них не покрыто, находится только живым запуском.
