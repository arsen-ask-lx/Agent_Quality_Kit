## Решения по механизмам

| Механизм источника | Решение для AQK | Доказательство / остаток |
|---|---|---|
| Ошибка инструмента не равна отсутствию находок | Уже реализовано в execution/run; исправляем нарушающую договор обёртку test-not-adjusted | fail-closed smoke + новая недоступная база |
| Не терять ошибку после фильтрации baseline/diff | Исправлены ratchet/native/capture; агрегатор уже работал правильно | gate-errors.test.mjs: fail + cannot, оба порядка, jobs 1/2; реестр не изменён при аварии |
| Свидетельство связано с входом проверки | Устранены две неоднозначности сериализации evidenceHash | Красные/зелёные units-evidence; report запускает проверки заново, LCOV-кэш не копируем |
| Worktree и пользовательские hooksPath | Исправлено обнаружение действительного хука | Живые Git-фикстуры до/после, относительный/абсолютный путь, старый неактивный hook |
| Сохранение чужих Git-хуков | Уже не перезаписываем: AQK делегирует установку pre-commit; своего установщика Git-хуков нет | не переносим второй installer только ради feature parity |
| Отказ при partial staging | Нужен отдельный опыт действующего способа запуска AQK через pre-commit | не добавляем глобальный запрет до проверки: Git-framework может прятать unstaged сам |
| Независимые настройки анализатора | Оценить на существующих native-рецептах AQK | отдельный корпус suppression; не включать все языки без инструментов |
| Tamper: тесты, skip, ослабление assert | Уже есть checkwash + test-has-assertion + gate-not-weakened | требуется общий корпус с законными изменениями, не второй regex-анализатор |
| Показ bypass и долга | Есть ratchet/advisory/skipped с явным выводом | сверить stderr/crash/просрочку, не импортировать legacy baseline с игнорированием всех findings |
| Реальные версии tools и проверка кэша | AQK не управляет таким npm-кэшем; vitals пока проверяет доступность | полезен отдельный протокол внешнего арбитра; версия без связи с конкретным запуском недостаточна |
| Diff coverage / CRAP / CC | Отдельный пилот измерения для AQK | не считать portable-вложенность CC, report coverage не считать LCOV |
| Удалять старые отчёты анализаторов | Проверить существующие native adapters до добавления механизма | кэш чужого code-quality не переносим |
| Полный/быстрый запуск | Уже есть doctor groups/only/skip/jobs и ограничения | не заводим второй верхнеуровневый runner |
| LLM-рецензия jev | Не включаем в ядро CLI: вендоронезависимый продукт без ключей/передачи кода | возможный внешний opt-in профиль требует eval-корпуса, пока точность не доказана |
| Авто-stop и разрешение после повторного FAIL | Не переносим как приёмочный гейт | не должен подменять проверку готовности |
| Запрет AI attribution/emoji | Отклонено | авторская редакционная политика, не свойство корректности AQK |
| Секреты, аудит зависимостей, возраст release | Секреты и pin уже сторожатся; возраст не равен безопасности | оценивать реальные зависимости проектов-получателей, не добавлять registry-запросы в CLI |
| UI/12 языков/агентские runtime adapters | Отдельные профили при наличии проекта-получателя | наличие таблицы языка не равно проверенной интеграции |

## Что изменилось в продукте

- test-not-adjusted: недоступная база или объект не типа commit → exit 2, doctor не считает
  это успехом. Доступный явно заданный диапазон работает и на одном коммите.
- evidenceHash: типизированные JSON-записи; удаление отличается от текста `<missing>`,
  нулевой байт не имитирует границу следующего файла. Хеш имеет новую версию входного формата;
  прежние хеши не совпадут с новыми даже при одинаковом входе. Они не используются как кеш.
- preCommitHook: путь определяет Git, включая worktree и hooksPath; тексты RU/EN больше
  не обещают, что действующий хук обязательно находится в `.git/hooks`.
- _native.sh: сначала классифицирует exit, потом фильтрует находки; при аварии сохраняет
  необработанный вывод. Находки native-инструментов нормализуются в exit 1 обёртки.
- ratchet.sh: авария не фильтруется baseline и не изменяет реестр.
- aqk ratchet: не создаёт baseline и не переписывает манифест при аварии/таймауте.
- _exit.sh: общий shell-договор для двух обёрток; копируется с native-гейтами и храповиком.
  Node и shell остаются разными runtime; их соответствие проверяется машиной.
- pylint: неподдерживаемые биты exit-кода больше не считаются находками.

## Первоисточники договоров

- [Git rev-parse](https://git-scm.com/docs/git-rev-parse): commit-ish и разрешение Git-путей.
- [Git hooks](https://git-scm.com/docs/githooks): каталог hooks может быть переопределён.
- [Pylint exit codes](https://pylint.readthedocs.io/en/latest/user_guide/usage/run.html#exit-codes):
  документированные биты находок и ошибка вызова 32.
- [Vulture](https://github.com/jendrikseipp/vulture#exit-codes): находки возвращают 3.

Прямого копирования стороннего исходного кода нет. Ни глобальных хуков, ни скиллов не ставили.
Публичная отправка и выпуск не выполнялись.

## Остаток цикла: не переходить к следующему репозиторию по числу прочитанных файлов

4. Partial staging: проверить фактический запуск AQK через pre-commit до введения собственного

5. По результату опытов принять/отклонить оставшиеся механизмы с причиной; только затем закрыть
   цикл и начать полный проход Matt Pocock. UI и LLM не добавляются в ядро CLI ради полноты списка.

## Пакет 3, опыт 1: конфигурация анализатора снимала находку

**Замер 2026-09-26** (ruff 0.16.7, pylint 4.0.8, vulture 2.16, Linux/WSL, Node 22.23.0).
Вопрос: можно ли выключить объявленную проверку, не тронув манифест. Храповик
`protection-not-removed` сторожит набор гейтов в `.aqk.yml`; конфигурацию инструмента,
который гейт зовёт, не сторожил никто.

Первый прогон замера был **недействителен** и записан как ошибка метода: инструмент запускался
из корня AQK, а не из подопытного проекта, и pylint, vulture и eslint своей конфигурации просто
не находили — три «защищено» были артефактом оснастки. Гейт запускает рецепт с `{dir}` = `.` из
корня проекта; повторный замер сделан так же.

| Рецепт | Приём | До правки | После |
|---|---|---|---|
| `ruff --select T20` | `ruff.toml extend-exclude` | **0 — зелёный** | 1 |
| `ruff --select T20` | `ruff.toml per-file-ignores` | **0 — зелёный** | 1 |
| `ruff --select T20` | `pyproject [tool.ruff] extend-exclude` | **0 — зелёный** | 1 |
| `ruff --select T20` | `ruff.toml lint.ignore` | 1 | 1 |
| `ruff --select BLE,TRY400,SIM105` | `extend-exclude` | **0 — зелёный** | 1 |
| `ruff --select FIX,TD` | `extend-exclude` | **0 — зелёный** | 1 |
| `pylint --enable=R0801` | `pylintrc ignore=src` | **0 — зелёный** | 1 |
| `pylint --enable=R0801` | `pylintrc ignore-patterns` | **0 — зелёный** | 1 |
| `pylint --enable=R0801` | `pylintrc disable=R0801` | 1 | 1 |
| `vulture --min-confidence 60` | `pyproject [tool.vulture] exclude` | **0 — зелёный** | 1 |
| `vulture --min-confidence 60` | `pyproject ignore_names` | **0 — зелёный** | 0 — оставлено сознательно |
| `eslint --no-config-lookup` | свой `eslint.config.mjs` | 1 | 1 |
| `eslint --no-config-lookup` | `eslint.config ignores` | 1 | 1 |
| `eslint --no-config-lookup` | `/* eslint-disable no-console */` | 0 | 0 — законно по `gate-not-weakened` |

Восемь зелёных гейтов при нарушении, лежащем в коде на месте. `eslint` защищён и до правки —
`--no-config-lookup` в рецептах стоял раньше и именно за этим; то есть решение у комплекта уже
было, но применено к одному инструменту из четырёх.

**Что изменилось в продукте.** Флаг, отменяющий исключение ПУТИ из конфигурации инструмента:
`--isolated` у четырёх рецептов ruff (`no-print-in-prod`, `swallowed-error`, `todo-without-task`,
`complexity-limit`), `--ignore= --ignore-patterns=` у pylint (`duplicate-code`), непустой
`--exclude` у vulture (`dead-code`). Каждый флаг сначала измерен на трёх входах: атака, атака на
чистом коде (не стало ли лечение ложным срабатыванием), нарушение без конфига.

**Что сознательно НЕ забрали и почему.** Подавление по ИМЕНИ: `# noqa: T201`,
`[tool.vulture] ignore_names`, `# pylint: disable=R0801`. Первое — `gate-not-weakened` намеренно
краснеет только на безадресном подавлении, и это записанное решение, а не упущение. Второе —
у `.aqkignore` нет замены именам: забрав `ignore_names`, получим находки на каркасных обратных
вызовах, то есть гейт выключат целиком. Цена названа в шапке `_native.sh`: подавление по имени
видно в дифе, исключение пути в конфиге — нет.

**Арбитр.** [`tool/selfcheck/smoke/analyzer-config.test.mjs`](../../tool/selfcheck/smoke/analyzer-config.test.mjs):
шесть проверок, все шесть красные до правки, зелёные после. Пять поведенческих гоняют рецепт
**из каталога** через `kit/gates/_native.sh` (строка рецепта не дублируется в тест и не разъедется),
шестая требует флаг изоляции у любого рецепта этих трёх инструментов — в том числе у того,
который заведут завтра. Общая приёмка: `doctor --run --min 1` → exit 0, 31/31.

**Границы.** Доказано для этих версий трёх инструментов и только для исключения пути. Остальные
ключи конфигурации (`select` в конфиге, `target-version`, whitelist vulture) не испытаны. Go, Rust
и TypeScript-рецепты этих записей не проверялись: прежняя граница «17 native-рецептов без
собственных образцов» остаётся. Windows CI здесь не запускался.

**Остаток опыта 1.** `--isolated` у ruff отменяет и законную конфигурацию проекта целиком
(`target-version`, `src`). Для рецептов с явным `--select` это ничего не отнимает, но проверено
это рассуждением, а не замером на живом проекте с нетривиальной раскладкой.
