# Корпус чужих починок

> **Что это.** Пары «коммит внёс беду → коммит её чинит» из живых репозиториев, где код пишут с
> нейросетью. Между этими двумя коммитами лежит класс брака, который **уже стоил человеку
> времени**, — в отличие от класса, придуманного нами из головы.
>
> **Зачем.** Каталог, который наполняет один автор, к сотне записей становится его вкусом.
> Разметка по чужим починкам — единственный известный нам способ мерить беду, а не себя. Это же
> закрывает самый старый долг проекта: чужой корпус изменений
> (`research/aqk-deep-research-2026-09-10.md`, §12). Решение владельца 2026-09-14.
>
> **Как воспроизвести:** `bash research/corpus/mine.sh 30` — нужен `gh` со входом.

## Метод и его границы

1. `gh search commits 'Co-Authored-By: Claude'` — коммиты, в теле которых стоит подпись агента.
2. Файлы этого коммита; по каждому — последующие коммиты, чьё сообщение начинается с
   `fix`/`revert`/`hotfix`/`bug`.
3. Пара считается находкой, только если правка трогает **те же файлы** и класс брака **называется
   словами**, по которым можно написать краснеющую проверку.

**Чего этот метод НЕ доказывает — и чего мы не будем утверждать.** Подпись агента в коммите не
значит, что код писал агент: подписью иногда помечают коммит, в котором агент написал только
сообщение. Причинную связь «агент внёс» мы доказать не можем. Утверждаем ровно то, что видно:
**эта беда случилась в живом проекте, и её чинили**.

## Случай 1 — «проверка нашла беду, не смогла оповестить и заключила `success`»

**Откуда:** `smith-horn/skillsmith`, коммит `e299dfd55a`, дословно из его сообщения (сверено
2026-09-14 через `gh api repos/smith-horn/skillsmith/commits/e299dfd55a`):

> pointer-autorepair correctly detected a real ADR-143 ancestry violation on c97d2078f, failed to
> open the alert issue, and concluded `success`. main then carried a docs/internal pointer 16
> commits off the main line and three PRs were silently blocked. A human found it days later by
> investigating one.

Корень, по их же словам, лежал в логе всё это время строкой выше проглоченного предупреждения:

> could not add label: 'submodule-pointer-regression' not found
>
> The label has never existed on this repo. […] Every alert this job has ever attempted failed this
> way; the R6 detection was simply the first FAIL to exercise a path that could not have worked.

И размер починки — их формулировка:

> Fixes five silent-success paths in one function

**Почему это важно нам.** Это наш класс в чистом виде и в чужом проекте, описанный самими
сопровождающими, с ценой: три pull request молча блокировались, нашёл человек спустя дни. Причём
проверка **не работала никогда** — метки, которую она создавала, в репозитории не существовало.

**Поймал бы это хоть один наш гейт? Нет.** `ci-actually-fails` смотрит на маскировку в YAML
(`|| true`, `continue-on-error`) и на закрытый список запускалок. Здесь маскировки нет вовсе:
есть путь внутри оболочечного скрипта, где неудача оповещения превращается в `::warning::`, а
функция возвращает ноль.

**Что это значит для нашего замера частоты.** 2026-09-14 мы посчитали: `|| true` и
`continue-on-error` — ноль на 93 строках проверок и ноль настоящих на 70 конвейерах, и записали
вывод «наш класс редкий». Вывод надо уточнить: мы **мерили там, где смотрит наш гейт**. Этот
случай показывает, что класс живёт в скриптах конвейера, куда мы не заглядываем. Редким оказался
не класс, а та его форма, которую мы умеем видеть.

**Заявка в каталог (черновик):** проверка сообщает о неудаче через `::warning::` и возвращает
ноль — путь молчаливого успеха внутри скрипта. Граница и способ проверки не продуманы; прежде чем
заводить запись, нужны ещё случаи этого же класса из корпуса — одного мало, это наше же правило.

## Замер 2026-09-23 — гипотеза из случая 1 проверена и закрыта нулём

Случай 1 оставил черновик заявки: «проверка сообщает о неудаче через `::warning::` и возвращает
ноль». Прежде чем заводить запись, форму замерили на чужом коде — и она оказалась почти
несуществующей.

Взяты 400 файлов конвейеров и скриптов из 220 репозиториев, где печатается аннотация GitHub
Actions (поиск по коду, один файл с репозитория). Считалось: есть ли в блоке, печатающем
`::error::`, хоть один путь к ненулевому коду возврата.

| | сколько |
|---|---|
| блоков, печатающих `::error::` | 379 |
| из них с ненулевым выходом рядом | **369** |
| откладывают вердикт в `$GITHUB_OUTPUT` | 4 |
| без выхода вовсе | 6 |
| **из них настоящих после разбора руками** | **0** |

Все шесть: учебный стенд из двух шагов (`3plepointinc/GithubActionsLab`), текстовый файл с
описанием задания, PowerShell-помощник, превращающий отчёт тестов в аннотации, библиотека
логирования (`Zebradil/AUR/scripts/lib/ga_logger.sh`, функция `log::error`) и блок, где
`::error::` стоит внутри комментария.

**Вывод.** «Напечатал ошибку и забыл упасть» в живом коде практически не встречается: `::error::`
пишут те, кто уже знает, что он не роняет шаг. Класс из случая 1 настоящий, но его форма — не
аннотация, а путь молчаливого успеха ВНУТРИ функции скрипта, и опознаётся он не текстом строки, а
графом выходов. Записи под это нет и не будет, пока не найдётся конструкция, которую видно без
понимания смысла.

**Что это стоило и что дало.** Полдня. И оно же увело в сторону, где замер дал класс: пара сводов
агента — `research/competitors/agents-md-check.md`, запись `entry-docs-agree`.

### Побочное число: удалённая запись про ссылки, замеренная заново

По дороге тем же способом проверена форма, которую каталог уже отверг: «свод ссылается на файл,
которого нет» (`entry-links-exist`, удалена 2026-09-15 — двенадцать ложных и **ноль подтверждённых
настоящих** на 400 репозиториях).

Замер 2026-09-23 по 300 репозиториям, но по **конструкции, а не по тексту**: только
markdown-ссылки вне блоков кода, адреса и пути от корня сайта отброшены, цель сверяется с деревом
репозитория, а не с диском.

| | сколько |
|---|---|
| сводов, где есть хоть одна ссылка на файл | 118 |
| сводов с битой ссылкой | 9 (8 репозиториев) |
| **подтверждено разбором руками** | **7** |

Настоящие: `docs/SECURITY.md` при `Docs/SECURITY.md` в дереве (`1amageek/SwiftAgent`);
`index.php` при `public/index.php` (`ShaneMcC/notespaste`); файл, переехавший между проектами
(`MofaggolHoshen/job-orchestrator`); относительная ссылка от неверного корня
(`Arize-ai/arize-skills`); и три пути, которых нет нигде. Ложные: `papers/example.pdf` — ссылка,
приведённая как ПРИМЕР оформления ссылок, и та же ссылка, посчитанная дважды в двух сводах.

**Это не основание вернуть запись — это основание спросить владельца.** Прошлое решение
(«хрупкую запись не чинят, её убирают») принято на замере, где настоящих было ноль; здесь их
семь, но одна из девяти находок — снова ссылка-пример, то есть та же грань. Решение об объёме —
в `PROJECT.md` §9.
