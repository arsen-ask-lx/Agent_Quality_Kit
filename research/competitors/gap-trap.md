## Вывод одной строкой

**Ближайший сосед по мысли из всех найденных.** Та же исходная посылка («правила — текст, и читает
их только тот агент, который их нарушает»), те же ходы: у каждого правила гейт, гейт доказывается
красным, храповик, «не смогли запустить» — код 2, а не зелёный. Разница в форме: у них навык, который
модель исполняет один раз и оставляет файлы в репозитории; у нас программа с каталогом записей и
образцов, которую можно гонять в конвейере.

## Что у них есть, чего нет у нас

**Proven red для тестов самого проекта.** Изменённые файлы тестов из pull request прогоняются в
копии на коде ДО изменения; тест, зелёный там, ничего не доказывает, и проверка падает. У нас
`prove` доказывает, что краснеет ГЕЙТ на своём образце, а про тесты проекта — только
`test-not-adjusted` (утверждение не ослабили) и `test-has-assertion` (тест вообще умеет упасть).
Вопроса «ловит ли новый тест ту беду, ради которой написан» у нас нет. **Заявка в каталог**, с их
оговорками, которые стоит взять целиком:

- судить каждый файл отдельно, иначе зелёный файл проезжает на красном соседе;
- различать красный «по утверждению» и красный «по отсутствующему символу» (`is not a function`,
  `Cannot find module`, `ImportError`): второй доказывает, что код новый, а не что утверждение
  кусается, — у них это предупреждение, а не зачёт;
- «запускалка не стартовала» — код 2, а не красный.

## Что нашли у них — письмо

[`pliablepixels/gap-trap#2`](https://github.com/pliablepixels/gap-trap/issues/2), 2026-09-27:

1. Вердикт выносится по файлу, а не по тесту: новый тест, зелёный на старом коде, проезжает, если
   в том же файле покраснел другой, изменённый тест. Воспроизведено на `ad07f43`, vitest 5.0.2,
   шаблон без правок: `✓ clamps when bounds are swapped` на старом коде — и «changed tests fail on
   the pre-change code, as they should», код 0. Их же шапка формулирует этот принцип для файлов.
2. Без `--title` скрипт всегда печатает usage и выходит с 2: при `titleIndex === -1` условие
   `i !== titleIndex + 1` выбрасывает первый аргумент. Конвейер их шаблона `--title` передаёт
   всегда, ломается только ручной запуск.

**Урок для нас, если возьмём заявку:** судить по тесту, а не по файлу, — с самого начала.

## Чего не берём

- Модельный допуск («навык работает только на старшей модели»): вердикт у нас выносит программа.
- Пропуск проверки по типу в заголовке (`refactor:`, `docs:`): заголовок пишет агент. У них это
  предупреждение в конвейере — то есть успех; ровно класс «`::warning::` вместо провала» из нашего
  корпуса (`research/corpus/README.md`, случай 1). Они называют это обходом вслух, и это честно, но
  для нас — не образец.
