## Что это на самом деле

«Линтер для обвязки агента»: оценка 0–100 по 51 детерминированной проверке в шести группах
(находимость 20%, инструкции 25%, работоспособность 18%, преемственность 12%, безопасность 15%,
настройка Claude Code 10%) плюс 7 необязательных: три зовут ИИ-субагента разбирать свод, четыре
читают логи Claude Code. Ядро — `src/scanner.sh`, 2252 строки оболочки и `jq`; печатает строку
JSON на проверку. Сверху: оценка (`scorer.js`), план исправлений и автопочинка (`plan-generator.js`,
`fixer.js`, шаблоны в `standards/fix-templates`), отчёт в терминал, HTML, **SARIF** и **пометки
GitHub Actions** (`scripts/emit-workflow-commands.js`). У каждой проверки — ссылка на источник
(`standards/evidence.json`): 265 версий системного промпта Claude Code, исходники Claude Code,
шесть статей.

Что проверяет: наличие и форму свода (F*, I*), команды сборки и тестов в своде, конвейер,
линтер, размер файлов, скорость хука перед коммитом (W*), файл передачи дел, план, журнал (C*),
`.env` в `.gitignore`, SHA у действий, сканер секретов, `pull_request_target`, личные адреса
почты в истории (S*), имена событий хуков, matcher, «предохранитель» у хука Stop, опасные
разрешения (H*).

## Близнецы: различает ли рабочую проверку от нерабочей

Два проекта, одинаковые во всём, кроме способности проверки провалиться: `"test": "node --test"`
против `"node --test || true"`, тест с `assert` против теста без него, шаг конвейера без
`continue-on-error` против `continue-on-error: true`, хук `npm test` против `npm test || true`.

**Итог: 71 и 71, все 51 проверка — одинаковые оценки.** Наша `ci-actually-fails` на тех же парах:
0 и 1. (`test-has-assertion` промолчала на обоих — «вызов без утверждения» у нас сознательно не
находка, граница записана в `.aqk.yml`.)

Их проверка, которая ближе всех к вопросу, — H7 «ворота в конвейере блокирующие»
(`scanner.sh:1951-1979`). Устроена так:

```sh
if printf '%s' "$wf_name" | grep -qiE '(required|gate|test-required|size|check)'; then
  ...
  if ! printf '%s' "$wf_content" | grep -qE 'exit[[:space:]]+1'; then
    h7_warn_only=$((h7_warn_only + 1))
```

То есть ворота — только файлы с `gate`/`check`/`required`/`size` в имени, а «блокирующие» — где
в тексте встречается `exit 1`. Опыт: те же близнецы, `ci.yml` переименован в `check.yml`, в
поддельный дописан комментарий `# on failure the step does exit 1`:

| | Что на деле | H7 |
|---|---|---|
| настоящий | `npm test` роняет шаг | «warn-only (always exit 0) — they never block merge» |
| поддельный | `continue-on-error: true` | «All 1 gate workflow(s) are blocking» |

Ровно наоборот в обе стороны.

## Ошибки, найденные при чтении и запуске

1. **Windows-переносы.** F7 (`scanner.sh:1267-1300`) берёт цель `@…` из строки вместе с `\r` —
   `AGENTS.md\r` не существует, подключение объявлено битым. У нас этот класс сторожит
   `mutation.sh` для каждой записи.
2. **Имя файла без каталога.** W5 печатает `basename`: `incidents/README.md` стал «README.md».
3. **Определения своих правил — находки.** S6/S7 краснеют на файлах, где шаблоны секретов и
   личных путей ОПИСАНЫ. Тот же класс, что мы закрыли у себя 2026-09-09 («определение записи —
   не находка»).
4. **Свод через `@AGENTS.md` не читается.** I6 и W1 смотрят только `CLAUDE.md`: «9 строк —
   слишком коротко», «команд нет». При этом I8 считает весь подгружаемый текст — «246 строк,
   слишком длинно». Два вердикта про один и тот же свод противоречат друг другу.
5. **«Жёсткие ограничения из исходников Claude Code» устарели.** Сверено с документацией
   2026-09-11:
   - «40 000 символов — файл молча обрезается» (I7) — документация: «Claude Code loads a
     CLAUDE.md file of up to 4 MiB in full and skips a larger file» (code.claude.com/docs/en/memory);
   - «файл больше 256 КБ не прочитать — жёсткая ошибка» (W5) — документация: целиком не влезает
     — «Read returns the first page with a `PARTIAL view` notice» (…/tools-reference);
   - «хук Stop без предохранителя крутится вечно» (H3) — документация: «Claude Code overrides the
     hook and ends the turn after 8 consecutive blocks» (…/hooks);
   - список допустимых событий хуков H1 — 12 имён (`standards/reference-thresholds.json`); у нас
     в `hook-actually-fires` 35, и `InstructionsLoaded`, `PostCompact`, `FileChanged` у них —
     «опечатка»;
   - «Claude Code never uses `--no-verify`» (обоснование W6) — anthropics/claude-code#40117:
     агент обходил ворота через `--no-verify` шесть коммитов подряд.
6. **«Точность 99%» — согласие с самим собой.** `tests/accuracy`: 4533 размеченных репозитория,
   точность по проверкам 0,99+. Но разметку делает `auto-label.js` по `check-spec.md`, который
   сам «Extracted from `src/scanner.sh`». Число меряет, что сканер совпадает со своим пересказом,
   а не что находит беду: F3 «проходит», если в своде есть слово `checklist`.

## Что брать себе

1. **Находки гейтов — пометками прямо в pull request.** В GitHub Actions строка
   `::error file=<путь>,line=<n>,title=<гейт>::<сообщение>` становится красной пометкой у строки
   файла. Наши гейты уже печатают «путь: находка», `scope.mjs` умеет пути разбирать — дописать
   печать этих строк под `GITHUB_ACTIONS=true`. Экранирование свойств и данных — сверить с
   документацией GitHub, а не с их кодом. SARIF — позже и только если попросят: пометки дают то
   же самое без загрузки файла и прав `security-events`.
2. **`learn`: правило есть, а человека всё равно поправляют.** Их SS2
   (`src/session-analyzer.js:824-880`): реплика с поправкой рядом с вызовом инструмента
   сверяется с правилами свода по ключевым словам. Наш `learn` ищет обратное — сказанное вслух и
   не записанное. Вторая половина ложится прямо в наш тезис: правило, по которому человек
   продолжает поправлять агента, текстом не держится — ему нужен сторож. Особенно правила с
   `<!-- aqk: человек -->`.
3. **Постоянный набор настоящих репозиториев — но с разметкой по свойству, а не по правилу.**
   Их идея замера точности на тысячах репозиториев правильная, исполнение круговое. У нас
   близнецы и случаи из журнала — это и есть разметка по свойству; не хватает только того, чтобы
   они жили в самопроверке, а не в памяти разборов.

## Чего не брать

- оценку 0–100 и веса групп — на близнецах одинаковая
- «золотые» пороги (свод 60–120 строк, число слов `IMPORTANT`) — выведены из системного промпта
  Anthropic, а не из замера на своде пользователя
- автопочинку чужих файлов (`fixer.js`) — у нас `aqk prompt` отдаёт задание агенту с арбитром у
  каждого пункта; править за человека без арбитра не будем
- W11 (`test-required.yml`) — их собственное соглашение, выданное за проверку
- ИИ-субагентов в проверке (D1–D3) — вердикт, который нельзя воспроизвести
