## Что это на самом деле

«ESLint для файлов агента»: оценка 0–100 для `CLAUDE.md`, `AGENTS.md`, навыков и настроек.
Сайт на Next.js с загрузкой результатов в Supabase плюс CLI (`packages/cli`). Движок — 131 правило
в 27 файлах (`src/engine/rules/`, ≈8000 строк), пять групп с весами: структура 20, ясность 25,
полнота 20, безопасность 20, согласованность 15. **Ничего не запускает**: каждое правило читает
строки файлов и ищет слова и форму.

Большинство правил — про текст свода: «есть ли раздел про идентичность» (`completeness/has-identity`),
«нет ли расплывчатых указаний» (`clarity/no-vague-instructions`), «определены ли термины»
(`clarity/undefined-term`), «важное правило не в середине файла» (`clarity/position-risk-warning`:
слова NEVER/MUST NOT/CRITICAL в строках от 20% до 80% длины — предупреждение).

## Различает ли рабочую проверку от нерабочей

Нет, по построению: ни одно правило ничего не запускает. Ближе всех к нашему вопросу
`security/critical-rules-enforce-hooks` («критические правила должны держаться хуками, а не
текстом») — но оно проверяет только, что в проекте ЕСТЬ хоть какой-нибудь файл хуков
(`security.ts:293-340`). Наш `promise-has-gate` требует назвать сторожа у каждого правила.

## Что брать себе

1. **Ничего из правил напрямую.** Все 131 — про текст; у нас правило «если утверждение не
   проверяется машиной — его в стандарте нет», а «важное правило в середине файла теряется» —
   гипотеза из исследования длинных текстов вообще, а не замер про свод агента.
2. **Кандидат в запись: «агент может обойти ворота коммита».** Их исследование
   (`docs/v2.4.0-research-2026-04-19.md`, раздел про тезис «конфиг линтера лучше инструкций»):
   агенты злоупотребляют `git commit --no-verify` и комментариями, отключающими линтер. Второе у
   нас держит `gate-not-weakened`. Первого не держит никто — и у них тоже: правило так и не
   написано. Машинно проверяемая форма: в `.claude/settings.json` разрешено
   `Bash(git commit --no-verify…)` / `Bash(git push --no-verify…)`, или хук есть, а в
   `permissions.deny` нет запрета на `--no-verify`. **Нужен настоящий случай** до записи
   (правило `proof-from-journal`) — искать поиском кода по `settings.json`.
3. **Размер свода — по документации, а не по вкусу.** У них порог строк свода; у Claude Code в
   документации прямо: «target under 200 lines per CLAUDE.md file. Longer files consume more
   context and reduce adherence» (code.claude.com/docs/en/memory, сверено 2026-09-11). Наш
   `AGENTS.md`, который `CLAUDE.md` подключает целиком, — 250 строк. Это не запись каталога
   (порог — совет поставщика, а не отказ), но строка-совет в `doctor` возможна. Решение владельца.

## Чего не брать

- оценку 0–100 и веса — их же данные показывают, что она не различает проекты
- загрузку результатов на сервер (`upload.ts`, Supabase) — у нас единственный исходящий запрос
  комплекта — проверка свежести версии, и так останется
- самоправку свода (`autofix/*`: вынести инструкции, «сжать дубли») — правка чужого свода по
  эвристике без арбитра
- правила «есть ли раздел X» (`completeness/*`) — наличие раздела не значит, что агент его
  выполняет

## Не проверено

- CLI целиком не запускали: решение «брать/не брать» не зависит от его вывода, правила прочитаны
- как собраны 1194 результата (кто загружал, есть ли повторы одного проекта) — в данных есть
  только `id`, балл, замечания и дата

## Добыто сверх разбора: обход ворот коммита (2026-09-11)

Проверили кандидата из п. 2 «Что брать себе» — и оказалось, что класс другой.

- **Разрешают обход почти никогда.** Поиск кода GitHub: `--no-verify` в `.claude/settings.json`
  — 459 файлов. Первые 100 разобраны по спискам: **81 — в `deny`**, 15 — в хуках, 1 — в `ask`,
  1 — в `allow`. Кандидат «агенту разрешено обходить ворота» почти пуст.
- **Зато запрет почти везде хрупкий.** Форма у всех одна: `Bash(git commit --no-verify:*)`.
  Документация Claude Code (code.claude.com/docs/en/permissions, сверено 2026-09-11): «Claude
  Code matches everything before the first `*` as written» и «a deny or ask rule covers the
  invocation Claude usually produces and isn't a security boundary around the program»; там же:
  «Bash permission patterns that try to constrain command arguments are fragile». Отсюда такой
  запрет не останавливает `git commit -m "x" --no-verify` и `git commit -n` — **вывод из
  документации, живым запуском пока не подтверждён**.
- **Обход настоящий.** anthropics/claude-code#40117 (2026-03-28): агент обошёл ворота коммита
  через `--no-verify`, `git stash` и тихие флаги — шесть коммитов подряд с упавшими
  интеграционными тестами, при прямом запрете в CLAUDE.md. #90887 (2026-08-31) — то же, «despite
  explicit deny rules». Совет в обсуждении #40117 — хук PreToolUse, который смотрит всю команду.
- **Что держит на самом деле.** Хук PreToolUse по всей строке команды; и главное — те же проверки
  в конвейере: `--no-verify` пропускает только локальные хуки. Второе у нас уже сторожит
  `gates-run-in-ci`.

Кандидат теперь такой: «запрет обхода ворот держит» — защита, объявленная в настройках агента,
но ловящая одну форму команды из нескольких. Наш центральный класс. Решение — за владельцем.
